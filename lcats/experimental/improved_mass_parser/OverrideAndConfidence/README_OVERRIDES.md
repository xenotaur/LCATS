# LCATS mass_quantities: extraction diagnostics and reviewed start overrides

## What is new

The two-stage parser still performs structural screening on untrimmed Gutenberg
text before narrative cleanup. New story publications now also create an
`extraction.json` in the same directory as `story.json`.

On **new** story creation, the parser looks for a *pre-existing*, human-reviewed
`override.json` in that story directory. If present, the parser performs the
normal structural screen, the normal narrative extraction, and normalization;
then it finds the verified opening within the extracted body and trims **only**
material before that opening. It does not replace the story with the short
review excerpt, discard any later story text, or change an existing story.
An override that cannot be matched unambiguously **prevents publication** with a
`ValueError` rather than risk corrupting narrative text.

## Layout

Copy the Python modules from `lcats/gatherers/mass_quantities/` into your
existing LCATS package directory. The companion `gatherer.py` is included for
completeness. Copy the directory tree under `data/mass_quantities/` to the
LCATS output root that `storymap.TARGET_DIRECTORY` resolves to, keeping each
`override.json` in its corresponding story subdirectory. Do not replace any
existing `story.json` files; this package includes **no** `story.json`.

Example (the real package has 757 overrides):

```
data/mass_quantities/a_case_of_sunburn__fontenay/
    override.json       # installed before first extraction
    story.json          # generated by LCATS when eligible
    extraction.json     # generated by LCATS after successful publication
```

If your `DataGatherer.path` is not `<project>/data/mass_quantities`, place the
provided per-story override directories under the actual `DataGatherer.path`.

## extraction.json (generated at runtime, not distributed)

A ground-truth-style record with:

- `gutenberg_id`, `title` (list), `authors` (list)
- `original_opening`: first **120 physical lines** of the untrimmed,
  Gutenberg-envelope-cleaned text, retaining blank lines
- `first_narrative_text`: first **80 physical lines** of the **saved** body,
  after normalization and any override
- `review_status`: `extracted` (NOT human-verified)
- `confidence`: `high`, `medium`, or `low` from the parser's existing
  `boundary_confidence` diagnostic. This is a heuristic based primarily on
  title/author identification; it is **not** a calibrated prediction of
  whether the narrative start is correct. An override does not automatically
  elevate confidence.
- `physical_lines_included`: 120; `extracted_lines_included`: 80
- `extraction_datetime`: ISO-8601 UTC timestamp
- `override_applied`: boolean

Change the `RAW_LINES` and `EXTRACTED_LINES` constants in
`extraction_records.py` if different excerpt sizes are desired. Actual excerpts
may be shorter when fewer physical lines exist. Extraction timestamps are set
at runtime, not at package creation.

## override.json (reviewed, never written by LCATS)

This package contains **757** precomputed override records corresponding to
stories marked `extra_frontmatter` in the most recent `frontstories.zip`
comparison. Each is based on the verified `first_narrative_text` and
`original_opening` in our 1,648-entry reviewed corpus. Each contains:
`gutenberg_id`, `title`, `authors`, `original_opening`,
`first_narrative_text`, `review_status=verified`,
`physical_lines_included`, `override_datetime`, and `override_reason`.

Four entries marked `extra_frontmatter` were **not** given overrides: 24247,
29897, 38302, and 72192. Their reviewed openings could not be matched
unambiguously at a physical line boundary in the latest extraction. See
`override_selection_report.json`. There are no overrides for the two
`needs_review` cases (15089 and 4674), for previously corrected starts, or for
absent/rejected stories. This honors the rule that only **identified failures
of the current extraction** receive an override.

**IMPORTANT:** Existing `story.json` is reused by the original parser and will
not be rewritten merely because an override is added. To apply an override to
an already extracted story, intentionally remove or relocate that **specific**
`story.json` and ensure the duplicate registry allows a fresh extraction, then
run that story through LCATS. Back up your corpus first. This package does not
perform those destructive steps for you.

The parser's original duplicate registry check still runs first, so an
already-registered title/author may be skipped even if the story file has been
removed. Resolve such conflicts using your existing registry workflow.

## Safety and limits

- The override is applied **after** structural rejection and existing narrative
  cleanup, never instead of them.
- New saved stories receive `extraction.json`; skipped, reused and rejected
  stories do not receive a new extraction record.
- The source snippet is the text returned by `prepared.cleaned.text`, before
  the mass_quantities narrative parser (the Project Gutenberg envelope is
  already removed by the source layer).
- The reviewed opening must match the first part of a physical output line,
  followed by at least 8 words and at least 18 words checked when available.
  Short headings are matched using following text, not heading alone.
- The override only trims a prefix from the normalized body; it does not
  restore narrative text that has already been lost by earlier parsing.
- The new write sequence is `story.json` publication, then atomic
  `extraction.json` publication, then registry update. A diagnostic write failure
  is propagated, so the batch stops with an explicit error rather than silently
  claiming a fully completed result. If this happens after story publication,
  the existing story file remains and needs operator reconciliation.

## Confidence integration (2026-11-24)

`_inspect_metadata()` now requests `return_diagnostics=True` from
`clean_gutenberg_story()` and carries `boundary_confidence` into the
extraction report. The value is forwarded to `extraction_record()` and
written to `extraction.json` after successful publication. Its accepted
values are `high`, `medium`, and `low`; the helper defaults to `low` for
backward compatibility with direct callers. The value does not override
structural screening or trigger human-review decisions.

Existing `story.json` outputs are reused and **will not** get a new or
updated `extraction.json` without a new extraction, consistent with the
package's pre-existing reuse policy.
