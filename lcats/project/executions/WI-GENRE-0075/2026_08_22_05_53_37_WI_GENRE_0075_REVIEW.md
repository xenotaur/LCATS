# Result

- **P1, path-escape (fixed):** `promote_sidecar_tranche()`'s only check on
  `lcats_id` was "non-empty string" - an absolute path or a `..`
  component in an otherwise schema-valid manifest record could place
  `dest_path` outside `dest_root`, letting a malformed manifest overwrite
  an arbitrary `genre.json` anywhere on disk. Added
  `_lcats_id_escape_error()`: rejects an absolute `PurePosixPath`, any
  `..` component, and the empty-parts case (`lcats_id` of `.`, which
  would otherwise write directly under `dest_root`); as defense in depth,
  also resolves the candidate path and confirms it is still a descendant
  of the resolved `dest_root`. Checked before schema validation, so an
  escaping ID is rejected regardless of whether the rest of the record is
  otherwise valid.
- **P2, orphan-bucket (fixed):** a typo'd or stale `lcats_id` with no
  destination story bucket was silently "promoted" into a new directory
  containing only `genre.json` - invisible to `discovery.py`'s canonical
  story discovery, which requires an immediate `story.json`
  (`discovery.py:63-82`). `promote_sidecar_tranche()` now requires
  `dest_root/<lcats_id>/story.json` to already exist before promoting;
  otherwise the record is rejected with a clear error and no directory is
  created.
- Both fixes applied directly (not deferred) - both were valid, present,
  and feasible to fix in this change per the standard triage checks.
- 6 existing tests that asserted a bare `dest_root` with no pre-existing
  `story.json` updated to create one first, matching the new invariant
  they were implicitly relying on becoming an explicit precondition; 2
  new tests added (`test_lcats_id_escaping_dest_root_is_rejected`,
