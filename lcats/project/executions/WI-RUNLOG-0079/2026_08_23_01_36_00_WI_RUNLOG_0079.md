# Result

Removed `_log_run_event()` entirely. `run_validation()` no longer owns
`run_start`/`run_end` emission (moved to the caller) but still emits its
per-item events (`story_cached`, `story_completed`,
`story_unexpected_error`, `run_aborted_fatal`) via a `log:
run_log.RunLog` parameter instead of a bare `log_path`. `_run_validate_mode()`
now wraps `run_validation()` **and** `write_validation_outputs()` in a
single `RunLog` scope — this is the actual fix the WI's acceptance
criteria were written around: the original code logged `run_end` from
*inside* `run_validation()`, before `write_validation_outputs()` ever
ran, so a real exception during output writing (a disk-full, a removed
directory) left a `run_end` already on disk implying success, with no
terminal event at all for the actual failure.

**Real implementation-time discovery, resolved with a small,
deliberate addition to the already-merged `lcats.utils.run_log`
module** (not originally in this WI's `artifacts_expected`, but
directly the kind of dogfooding-driven gap this WI's own Summary
describes finding): `RunLog.__exit__`'s automatic clean-exit `run_end`
is always bare (no fields) — but the reference implementation's
`run_end` has always carried a rich payload (`run_id`, `aborted`,
`processed_count`, `error_count`, `agreement_count`,
`total_estimated_cost_usd`), and the WI's own acceptance criterion
("event shape ... unaffected") required preserving it exactly. Rather
than lose that payload or invent a new event name, added a minimal,
backward-compatible tracking flag: `RunLog.event()` now marks when the
caller has manually logged `"run_end"` itself, and `__exit__` skips its
own redundant auto-emission when that flag is set. This lets
`_run_validate_mode()` call `log.event("run_end", **rich_fields)` as
the literal last statement before the `with` block exits cleanly —
guaranteeing it only fires once output writing has actually succeeded,
while an unexpected exception anywhere in the wrapped scope still
correctly falls through to `RunLog`'s existing `run_aborted_unexpected`
path. Added 2 new tests to `run_log_test.py` covering this addition;
all 16 pre-existing tests there pass unchanged.

Added `test_output_write_failure_produces_run_aborted_unexpected_not_run_end`
to `run_prefilter_test.py` (there was no prior coverage of
`write_validation_outputs()` failing mid-write) — patches
`write_validation_outputs` to raise, asserts the exception propagates
(not swallowed) and the log shows `run_aborted_unexpected` as the final
event, never a `run_end`.
