# Summary

Implemented WI-PROMOTE-0097 (Stage 1 of `WS-PROMOTE-MODE-REDESIGN`):
restructured `lcats promote`'s CLI so an explicit `insert`/`upsert`/
`replace` mode is mandatory, and built a shared sidecar-validator
registry covering all 4 produced sidecar kinds.

# Result

- `src/lcats/analysis/corpus/promote_cli.py`: `build_parser()` now uses
  `add_subparsers(dest="mode", required=True)` with three subcommands
  (`insert`, `upsert`, `replace`); a bare `lcats promote` invocation
  refuses (`SystemExit(2)`) rather than defaulting to any behavior.
  `replace` keeps today's `collections`/`--source`/`--dest`/`--dry-run`
  arguments unchanged; `insert`/`upsert` share `--sidecar`,
  `--tranche-manifest`, `--dest`, `--allow-unvalidated`, `--dry-run`.
- `src/lcats/analysis/corpus/sidecar_validators.py` (new): a registry
  mapping `genre.json`/`scenes.json`/`linguistics.json`/
  `linguistics.tokens.json` to validator callables. `promote.py` imports
  only this module, never `genre_sidecar.py` or
  `analysis/linguistics/sidecar.py` directly. The linguistics validators
  are lazy-imported inside their wrapper functions (not at module load),
  so importing the registry never pulls in `linguistics/sidecar.py`'s
  heavier `event_role_world.surface_feature_extractor` dependency chain
  unless a linguistics kind is actually promoted. A basename-collision
  guard runs at registration time; `resolve_sidecar_filename()`
  implements the bare-name-assumes-`.json` / any-dot-is-exact rule.
- `src/lcats/analysis/corpus/promote.py`: generalized
  `promote_sidecar_tranche()` into `promote_sidecar_insert()`
  (create-only) and `promote_sidecar_upsert()` (create-or-overwrite),
  sharing one `_promote_sidecar_manifest()` engine. Manifest lines are
  now envelopes (`{"lcats_id": ..., "payload": ...}`) rather than bare
  sidecar records, so destination routing works uniformly across every
  registered kind, including `scenes.json` (whose payload carries no
  story-identity field of its own). `--allow-unvalidated` only bypasses
  the no-registered-validator case; a registered validator's own
  rejection is never bypassable. The pre-existing legacy-flat-genre
  refusal guard (`WI-GENRE-0076`) is preserved, gated to `genre.json`
  only, applied before both insert's and upsert's overwrite checks.
  `replace`'s own mechanism (`_copy_collection`/`promote_collections`)
  is untouched.
- `src/lcats/cli.py`: updated the top-level `promote` subcommand's
  help/description text to reflect the new mode requirement.
- `tests/analysis_tests/promote_test.py`: rewrote the tranche-mode test
  class into `PromoteSidecarInsertUpsertTest` (envelope shape, insert
  vs. upsert semantics, the scenes-payload-with-no-identity-field case,
  unregistered-kind refusal, `--allow-unvalidated` narrow-scope
  behavior), updated `PromoteCliTest` for the mandatory mode argument,
  and added `SidecarValidatorsRegistryTest` for the registry itself.
- `docs/reference/corpus-promotion.md`, `docs/reference/cli-commands.md`,
  `docs/reference/prepare-corpora-release.md`: updated every documented
  invocation to the new mandatory-mode syntax.
- Diff-mode self-review (cold-context subagent) found no issues;
  independently re-verified its two most load-bearing claims directly
  (bare-invocation refusal, lazy-import isolation of
  `linguistics.sidecar`) before pushing.
