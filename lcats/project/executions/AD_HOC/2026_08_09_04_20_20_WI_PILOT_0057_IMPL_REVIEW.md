Addressed 6 real GitHub review findings on PR #271 (WI-PILOT-0057
implementation): `experiments/03_cross_segment_relation_pilot/measure_prompt_caching.py`
identified stories by bare filename instead of real ID, ignored the

`anthropic_backend_test.py` that didn't actually test what its name
claimed.

# Result

- `report["stories"]` now uses `run_pilot._story_identity(s)` (real
  collection-qualified ID) instead of `s.name` (always `"story.json"`).
- `_fixture_stories()` accepts an optional `fixtures_dir` param, honoring
  `run_comparison`'s own `source_root` instead of hardcoding the script's
  own `fixtures/` dir.
- New `_warm_segmentation_checkpoints()` runs segmentation for every
  story once, before either comparison arm starts recording, so neither
  arm's recorded totals are skewed by which one happens to pay for
  segmentation first.
- `_extract_and_relate` (renamed from `_segment_and_extract`) now calls
  `run_pilot._run_erw_pipeline` instead of `_run_erw_extraction`, so the
  real `story_relation` cross-segment-relation pass — previously never
  exercised at all, since `_run_erw_extraction` explicitly excludes it —
  is actually measured.
- New `_MODEL_PRICING_PER_MTOK` (verified live against
  platform.claude.com/docs pricing, 2026-08-09) and `_compute_cost_usd()`
  add a real dollar-cost figure per arm and a `cost_delta_usd` in the
  report, per the WI's own acceptance criteria.
- `anthropic_backend_test.py`: renamed the misleadingly-named
  `test_cache_fields_default_none_when_absent_from_usage` (its helper
  always set the fields to `None`, never actually omitted them) to
  `test_cache_fields_none_when_present_but_null_on_usage`, and added a
  new `test_cache_fields_default_none_when_the_sdk_omits_the_attribute_entirely`
  that genuinely exercises the `getattr(usage, ..., None)` fallback
  against an SDK object lacking the attribute.
- A second independent-review pass on these fixes caught that the new
  cross-segment-relation test's docstring overclaimed ("actually runs
  when its own real gate is met") when the trivial dry-run fixture it
  uses can never satisfy that real `>=2-segments-with-events` gate;
  fixed by correcting the docstring to state what the test actually
  proves (the call site is reached), not the test logic itself, since
  the gate-met/gate-not-met behavior is already covered separately in
  `run_pilot_test.py`.
