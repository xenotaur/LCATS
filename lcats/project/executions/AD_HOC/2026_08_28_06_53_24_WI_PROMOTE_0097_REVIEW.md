# Summary

Review-response round for PR #405 (`WI-PROMOTE-0097` implementation).
The PR's automatic first-push review surfaced 7 real findings across
two reviewers: 4 from `copilot-pull-request-reviewer` and 3 P1 findings
from `chatgpt-codex-connector`.

# Result

- **Unsafe `--sidecar` filenames under `--allow-unvalidated` (P1,
  fixed)**: an arbitrary, unregistered `--sidecar` value could contain
  `..`/`/` (escaping the story bucket) or name `story.json` itself
  (letting `upsert --allow-unvalidated` silently overwrite the story).
  Added `_sidecar_filename_is_safe()` in `promote.py`, called
  unconditionally in `_promote_sidecar_manifest()` before any path is
  constructed.
- **Payload/envelope identity mismatch (P1, fixed)**: an
  identity-bearing payload (e.g. `genre-sidecar-v1`, carrying its own
  top-level `lcats_id`) could disagree with the envelope's routing
  `lcats_id` and still be written — silently attributing one story's
  content to another. Added a mismatch check: when `payload` is a dict
  with its own `lcats_id`, it must equal the routing `lcats_id` or the
  record is rejected.
- **Bare genre-sidecar-v1 manifests broken (P1, fixed)**: the
  unconditional envelope requirement rejected every record in the real,
  committed `WI-GENRE-0004`/`experiments/05_metadata_genre_prefilter`
  manifest (no `payload` wrapper), removing the only existing
  end-to-end tranche workflow (`WI-GENRE-0077`). Added a documented
  bare-record compatibility path: a manifest line with no `"payload"`
  field is accepted when it carries its own non-empty top-level
  `lcats_id` — the whole record becomes the payload, using that same
  `lcats_id` for routing. Resolves the open Risk Note this WI's own
  authoring left unresolved.
- **Write-path exception aborts the whole run (fixed)**: a `json.dumps`
  failure or `_atomic_write_text` `OSError` on one manifest line
  previously propagated and aborted the entire run instead of producing
  a per-line rejection. Wrapped the write in `try`/`except
  (TypeError, ValueError, OverflowError, OSError)`.
- **Misleading validator registry type annotation (fixed)**: `ValidatorFn`
  claimed every validator returns `genre_sidecar.ValidationResult`
  specifically, but the linguistics validators return a different
  (structurally identical) class. Replaced with a `Protocol`
  (`_ValidationResultLike`) describing the shared `valid`/`findings`
  shape both classes actually expose.
- **Stale survey-gating docstrings (fixed)**: `promote_cli.py`'s module
  docstring and `run()`'s docstring both claimed all promote modes are
  survey-gated; only `replace` runs the special-character survey.
  Updated both to say so explicitly.
- Updated `WI-PROMOTE-0097.md`'s own Risk Notes to record the
  bare-record-compatibility resolution (striking the prior open
  question) and the two new P1 findings, plus a small addition to the
  manifest-envelope acceptance criterion documenting the compatibility
  path and the mismatch rejection.
- Added 6 new tests covering all 4 code-level fixes (filename safety
  across 6 unsafe-name cases, identity mismatch rejection + matching-ID
  acceptance, write-failure-as-rejection via a mocked `OSError`,
  bare-record promotion, and the "neither payload nor own lcats_id"
  rejection case); updated one pre-existing test whose fixture is now
  correctly reinterpreted as a bare legacy record instead of a
  payload-missing envelope.
