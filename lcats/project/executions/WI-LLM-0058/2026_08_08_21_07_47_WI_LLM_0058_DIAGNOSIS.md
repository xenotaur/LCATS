# Summary

Implemented WI-LLM-0058: fixed the `secondary_genre` schema-adjacent
field corruption via output sanitization (candidate 2 from the WI's own
Scope), consolidated both real-API runs' evidence, and wrote the go/no-go
recommendation for `WI-ASSESS-0051`'s `--full` corpus run.

# Consolidated finding

Combined across two independent real-API runs (this repo's own
`WI-ASSESS-0051` 20-story sample and the prior `WI-ANNOTATE-0054`
24-story run): **17/44 real stories (39%)** had a corrupted
`secondary_genre` value containing a leaked fragment of the *next*
schema field's (`specials_verdict`) opening tag. Root cause: an
intermittent `claude-opus-4-8` structured-output reliability issue at
that specific field boundary — confirmed (by `WI-ANNOTATE-0054`, prior to
this item) **not** a parsing bug in this codebase (the corruption is
present in the value the Anthropic SDK's own already-parsed
`tool_use.input` dict contains) and **not** prompt injection (neither the
story text nor `ASSESSMENT_TOOL`'s schema/prompts contain any such tags).
`detected_genre` — the field `WI-ASSESS-0051`'s census actually reports —
was clean in **both** real runs (0/44 affected).

# Result

- `lcats/src/lcats/analysis/corpus/assess.py`: added
  `_sanitize_secondary_genre()` (detects any `<`/`>` character — a
  legitimate genre tag never contains one, and the heuristic catches all
  10 real corrupted examples in `stats_report.md` plus this item's own 7)
  and a new `AssessmentResult.secondary_genre_sanitized: bool` field.
  Sanitization happens in `assess_story()`'s success-path return only;
  `AssessmentResult.error` is never populated by this path, per the WI's
  explicit requirement (`annotate.py`'s `_annotate_genre` treats any
  `.error` as an unrecoverable failure and discards `genre.json`
  entirely — at a 39% corruption rate, routing through that channel
  would have turned cosmetic single-field corruption into widespread
  required-field data loss).
- `lcats/tests/analysis_tests/assess_test.py`: 3 new/modified tests —
  corruption gets sanitized + flagged with `error` staying empty and
  every other field (`detected_genre`, `summary`, `verdict`) still
  populated normally; 3 differently-worded corruption variants all
  caught by the broad heuristic; existing passthrough/defaults tests
  extended to assert `secondary_genre_sanitized` is correctly `False`
  for clean values.
- `experiments/04_genre_census/run_census.py`: bumped
  `_CLASSIFIER_VERSION` `"v1"` → `"v2"` (verified this constant is
  folded into the checkpoint fingerprint via `_fingerprint()`) so a
  resumed `--full` run re-classifies rather than silently serving a
  stale pre-fix cached (corrupted) value.
- **Schema reordering (candidate 1) explicitly deferred**, not
  implemented — no new paid API spend without an explicit go-ahead gate
  (per `forbidden_actions`/Non-Goals), and sanitization alone already
  resolves the practical downstream risk per the WI's own Risk Notes
  ("should be preferred if schema reordering's effectiveness can't be
  cheaply confirmed").
- `WI-ASSESS-0051`'s `depends_on: [WI-LLM-0058]` was already landed via
  PR #257 — no further action needed for that Required Change.
- PR: https://github.com/xenotaur/LCATS/pull/267

# Go/no-go recommendation for WI-ASSESS-0051's --full run

`WI-ASSESS-0051`'s census reports — was clean across all 44 real stories

`annotate.py`'s hard-failure `.error` channel in a different caller) is
resolved by this PR's sanitization fix. No further diagnostic spend is
required before approving `--full`.
