# Summary

Implement `WI-RELEASE-0038`: give LCATS an `lcats.version` module, a
`lcats --version` CLI flag, and a `scripts/version` release helper
(`tools`/`verify`/`tag`/`push`), mirroring LRH's `lrh.dev.versioning`
pattern but scoped to LCATS's actual toolchain.

# Result

Created:
- `lcats/src/lcats/version.py` — `importlib.metadata`-based
  `get_installed_version()`/`format_cli_version()`, mirroring
  `lrh.version`'s shape exactly.
- `--version` on the `lcats` CLI's top-level parser
  (`lcats/src/lcats/cli.py`), wired via `argparse`'s built-in
  `action="version"`, computed fresh from `version.format_cli_version()`
  on every `build_parser()` call — not a hardcoded string.
- `lcats/src/lcats/dev/versioning.py` — `tools`/`verify [tag]`/
  `tag <tag>`/`push <tag>` subcommands, structurally mirroring
  `lrh.dev.versioning` (idempotent tag/push behavior, clean-tree-gated
  `verify`) but with `tools`'s toolchain list scoped to LCATS's actual
  `dev` extras (python, ruff, black, pip — no pylint/pyright, which
  LRH checks but LCATS doesn't declare) per the WI's own Risk Notes.
  Uses `lcats.utils.paths.find_pyproject_root()` (built in
  `WI-PACKAGING-0036` specifically to replace hardcoded parent-depth
  indexing) for `cwd` resolution, rather than reintroducing the
  `parents[N]` pattern that helper exists to eliminate.
- `lcats/scripts/version` — thin wrapper (`python -m
  lcats.dev.versioning "$@"`), deliberately *not* copying LRH's
  `PYTHONPATH` manipulation: LCATS's other scripts
  (`test`/`lint`/`format`) rely on the editable install from
  `scripts/develop` with no `PYTHONPATH` handling, so this follows the
  same established local convention instead of LRH's.
- Tests: `tests/version_test.py`, `tests/dev_tests/versioning_test.py`
  (mocking `_run_command` as the subprocess/git boundary, per
  `AGENTS.md`'s "mock only at true boundaries"), and two new
  `--version` cases in `tests/cli_test.py`.

One implementation-time environment note: the `LCATS` conda
environment's editable install pointed at a different, stale worktree
at the start of this session; re-ran `scripts/develop` from this
checkout before validating.
