**Real bug found and fixed mid-implementation (not in the original WI
plan)**: `[tool.setuptools_scm] root = ".."` was required in addition to
`fallback_version`. Discovered via `SETUPTOOLS_SCM_DEBUG=1 python -m
setuptools_scm`, which showed `search_parent_directories=False` and
"using static fallback workdir" — without `root = ".."`, setuptools_scm
can't find `.git` (which lives one level above `lcats/`, since `lcats/`
is a subdirectory of the repo, not the repo root) and silently falls
back to `fallback_version` on every single build, meaning the acceptance
criterion "reports a version derived from the git tag, not a hardcoded
string" would have been *unmet* despite `dynamic = ["version"]` being
correctly configured. Verified the fix rigorously: created a throwaway
empty commit, confirmed the reported version changed from the clean tag
(`0.1.0`, at the tag) to a dev-suffixed SCM version
(`0.1.1.dev1+g<hash>`, one commit past it) — ruling out a coincidental
match between the fallback value and the tag — then removed the
throwaway commit (`git reset --soft` + amend, safe since nothing had
been pushed yet) before finalizing the real implementation commit.
