# Result

- `src/lcats/visualize/sources.py` — `load_corpus_stories()` loads every
  story's text keyed by a stable `story_id` derived from
  `discovery.iter_collection_story_files`'s paths (not
  `Corpora.get_corpora()`, which discards path identity — the exact gap
  the WI's own review round caught and required fixing).
  `load_candidates_genre_membership()` loads per-story
  `target_candidates` from `candidates.jsonl`, joined on that same
  `story_id`. Generalized the private path-resolution helper to
  `_resolve_repo_relative_path`, reused by both the existing
  `genres`-command loader and the new loaders.
- `src/lcats/visualize/analysis.py` — `word_frequencies()` reuses
  `story_analysis.get_keywords`/`top_keywords` rather than
  reimplementing tokenization.
- `src/lcats/visualize/rendering.py` — generalized
  `plot_genre_wordcloud`/`plot_genre_bar_chart` into shared
  `plot_wordcloud`/`plot_bar_chart` primitives (verified existing
  signatures/behavior unchanged), plus new
  `plot_word_frequency_wordcloud`/`plot_word_frequency_bar_chart`
  wrappers.
- `src/lcats/visualize/cli.py` — registers `words` under the existing
  `lcats visualize` command group (no top-level `cli.py` changes needed;
  `WI-VISUALIZE-0073` already registered the `visualize` subparser
  group). For genre-subset runs, asserts every `candidates.jsonl`
  `story_id` resolves in the loaded corpus snapshot before filtering
  (raises `ValueError` otherwise) and emits dual revision identifiers
  (corpus + `candidates.jsonl`); whole-corpus runs emit only the corpus
  identity.
- Full test coverage: unit tests for the new `sources`/`analysis`
  functions, rendering tests for the generalized primitives and new
  wrappers, and CLI integration tests covering the whole-corpus case,
  the genre-subset case (including dual-revision disclosure), and the
  join-completeness assertion.
