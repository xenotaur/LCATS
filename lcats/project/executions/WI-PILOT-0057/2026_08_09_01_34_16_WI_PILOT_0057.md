# Summary

Implemented WI-PILOT-0057 (WI 2 of WS-PILOT-COST-SUSTAINABILITY): an
opt-in Anthropic prompt-caching mechanism scoped to the tools+system
prefix, plus a measurement script for the real, explicitly-gated
comparison run (not yet executed - requires separate approval).

# Result

- **Required Change 1** (`lcats/src/lcats/llm/anthropic_backend.py`):
  `AnthropicBackend` gains `enable_prompt_caching: bool = False`. When
  enabled, `cache_control: {"type": "ephemeral"}` is attached to the
  `system` prompt (converted to Anthropic's block-list form, since a
  bare string cannot carry cache_control) and to the tool dict (copied
  via `{**tool, ...}`, not mutated in place - extractor tool schemas
  are shared module-level constants, e.g. `ENTITY_TOOL_SCHEMA`, and
  in-place mutation would leak caching into every other call site
  sharing that dict).
- **Required Change 2** (`lcats/src/lcats/llm/backend.py`):
  `BackendResponse` gains `cache_creation_input_tokens`/
  `cache_read_input_tokens: Optional[int] = None`, populated via
  `getattr(usage, "...", None)` (both fields are `Optional[int]` on the
  real SDK's `Usage` type). Verified no existing `BackendResponse(...)`
  construction site uses positional args for `raw` before adding these
  new fields, so no call site broke.
- **Required Change 3** (`measure_prompt_caching.py`'s
  `preflight_prefix_token_counts`): counts each of the 5 ERW
  extractors' tools+system prefix via Anthropic's free (non-generation)
  `count_tokens` endpoint, called from `main()`'s real (non-dry-run)
  path only, included in the written report.
- **Required Change 4** (new `experiments/03_cross_segment_relation_pilot/measure_prompt_caching.py`):
  reuses `run_pilot.py`'s own private helper functions
  (`_build_erw_extractors`, `_segment_story_cached`,
  `_run_erw_extraction`) unmodified, so the real per-segment
  interleaved call order (entity -> event -> relation -> discourse per
  segment) is preserved exactly, not reimplemented. A
  `_RecordingBackend` wrapper observes every real call's cache stats
  without changing behavior. A `--dry-run` mode
  (`_DryRunFakeBackend`, dispatching on tool name rather than call
  order/count, so a checkpoint hit on the second comparison arm can't
  shift which call it thinks is segmentation) proves the wiring at
  zero cost.
- `run_pilot.py` itself is **unchanged** - an earlier draft had added
  an `--enable-prompt-caching` CLI flag there, which a self-review pass
  correctly flagged as violating the WI's own Non-Goals ("Does not
  change run_pilot.py's own targeted-run harness beyond using its
  fixture set as the measurement target") - reverted; the measurement
  script constructs `AnthropicBackend` directly instead, which was
  already sufficient.
- **Real measurement run not yet executed** - Required Change 3's
  own scope ("before any real call") and the WI's own Risk Notes both
  gate this behind a separate, explicit human approval this PR does
  not itself request.
