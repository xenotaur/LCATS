# Summary

Implement WI-EVENT-0033 (Category C): schema-harden `scene_analysis.py`'s
`make_segment_extractor`/`make_semantics_extractor` and
`story_analysis.py`'s `make_doc_classification_extractor` with the `tool=`
structured-output path, per the audit's finding that unconstrained
`json_object` mode caused a 65% `parsing_error` exclusion rate in real
WI-EVENT-0030 dogfooding.

# Result

Prep fix: `WI-EVENT-0033.md` was missing a `## Required Changes` section
(same gap `WI-EVENT-0032` had) — `lrh work-items readiness` reported
`prompt_ready: no`. Added a concrete `## Required Changes` section
encoding a design verified directly against `llm_extractor.py`'s two code
paths (tool_schema vs. json_object), not just prose — `readiness` now
reports `prompt_ready: yes`.

**Design (verified, not assumed):** the tool_schema path never applies the
`output_key` unwrap the json_object path does, and
`result_aligner`/`result_validator` run *before* any unwrapping either
way, confirmed by reading `llm_extractor.py`'s `extract()` directly.

- `SEGMENT_TOOL_SCHEMA` (scene_analysis.py) keeps its `"segments"` wrapper
  key — required so `text_segmenter.segments_result_aligner`/
  `segments_auditor` (both read `parsed_output["segments"]` internally)
  keep working completely unchanged. The one unavoidable consequence:
  `extracted_output` becomes `{"segments": [...]}` instead of a bare list
  — fixed at both real consumers: `story_processors.py:142` and
  `run_pilot.py`'s `_segment_story:277`.
- `SEMANTICS_TOOL_SCHEMA`/`DOC_CLASSIFICATION_TOOL_SCHEMA` get **no**
  wrapper key (top level = the judgment's/classification's own fields
  directly) — neither extractor has a `result_aligner`, so
  `extracted_output` stays byte-identical to today's `output_key` unwrap.
  Zero consumer changes needed for either.

All three schemas hardened via WI-EVENT-0032's shared
`lcats.llm.tool_schema.strict_tool_schema()` helper.

**Known, deliberately out-of-scope:** `notebooks/12_extract_scenes.ipynb`
consumes `make_segment_extractor`'s output as a bare list directly and
will break under the new wrapped shape. Per `AGENTS.md` ("do not edit
Jupyter notebooks unless explicitly requested"), left untouched — flagged
in the PR and here for whoever next touches that notebook.

**Not verified in this environment:** no `ANTHROPIC_API_KEY`/
`OPENAI_API_KEY`/`.secrets/` configured (same constraint noted throughout
WI-EVENT-0030's history). The acceptance criterion requiring a live
re-run against the sampled story set that saw the 65% exclusion rate,
reporting the new rate, is **not done** by this execution — needs whoever
has credentials to run it for real.
