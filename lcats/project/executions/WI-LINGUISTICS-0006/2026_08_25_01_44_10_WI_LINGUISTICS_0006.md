# Summary

Implemented `WI-LINGUISTICS-0006`: a deterministic
`linguistics-lexicon-v1` materialized lexical artifact derived from
`linguistics-token-detail-v2`.

# Result

- Added `lcats.analysis.linguistics.lexicon` with a versioned schema builder,
  validator, source-token-detail fingerprinting, query index, and representative
  query benchmark helper.
- The lexicon records story identity, source token-detail SHA-256 and
  provenance, derivation version, token/sentence/row denominators, and sorted
  `(surface, lemma, upos)` count rows.
- Added `--include-lexicon` to the linguistics CLI and runner. The option is
  explicitly tied to `--include-token-detail --token-detail-version v2`, writes
  `linguistics.lexicon.json` atomically beside the compact and token-detail
  artifacts, participates in redirected output paths, and appears in run
  summaries as `include_lexicon` and per-result `lexicon_path`.
- Existing-output handling now validates requested lexicons against the
  existing v2 token detail before skipping. Missing, stale, unreadable,
  malformed, or non-regenerating lexicons fail without replacement unless
  `--existing overwrite` is selected.
- Stopword, noun-family, top-N, and genre policies are not embedded in the
  generated artifact; they remain query-time policies over the stored facts.
- Added schema documentation in `docs/reference/linguistics-lexicon.md` and
  linked the new artifact from `docs/reference/linguistics-sidecar.md`.
- No full-corpus run was performed. No generated linguistic sidecars were
  promoted into `corpora/`.

Proactive diff-mode self-review found one real P2 issue: Python accepted JSON
booleans as integer count/denominator fields because `bool` subclasses `int`.
The implementation was fixed with bool-excluding integer checks, canonical JSON
regeneration comparison, and regression coverage for direct validation and
runner resume behavior.
