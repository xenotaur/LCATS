function, matching `_log_run_event()`'s open-append-write-close shape)
and `RunLog` (context manager). `RunLog.__init__` accepts either a bare
`working_root` or a `checkpoint.CheckpointRoots` and always re-runs
`checkpoint.resolve_roots()`'s protected-root guard regardless — never
trusts a caller-supplied `CheckpointRoots` as pre-validated, closing the
specific gap Codex/Copilot flagged on PR #352 (`CheckpointRoots` is a
bare frozen dataclass with no validation marker). `RunLog.__exit__`
emits `run_end` on clean exit, `run_aborted_fatal` for an exception
matching the caller-supplied `fatal_exceptions` tuple, and
`run_aborted_unexpected` for anything else — the explicit-classifier
form the WI's acceptance criteria named as one of two acceptable
mechanisms. Also creates `working_root` via `mkdir(parents=True,
exist_ok=True)` after validation succeeds (a real gap unit testing
surfaced — see Validation below), since `log_event()` only opens in
append mode and never creates directories itself.

Created `lcats/tests/utils_tests/run_log_test.py` with 12 tests covering
both entry points: append-per-call behavior, crash-safety (readable on
disk immediately after each call, not buffered), protected-root
rejection via both a bare `Path` and a directly-constructed
`CheckpointRoots` (the exact PR #352 bypass vector), and all three
`__exit__` paths (clean/fatal/unexpected).
