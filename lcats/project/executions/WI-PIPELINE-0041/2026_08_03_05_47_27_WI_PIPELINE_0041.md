# Summary

Migrate `run_pilot.py` from in-memory-only, write-at-the-end execution to
staged, checkpointed execution using `WI-PIPELINE-0040`'s
`lcats.utils.checkpoint` helper, fix the story-discovery selector for the
bucket-world corpus layout, and re-vet against this session's 8
operational criteria — per `WI-PIPELINE-0041`'s acceptance criteria.

# Result

- Four independently checkpointed stages, per Decision 3: `genre_detect`
  (per scanned candidate, in `build_stratified_sample`), `segment`,
  `erw_extract`, and `cross_segment_relation` (per selected story, in
  `run_story`) — each with its own fingerprint (model/backend/pipeline
  version; the two downstream stages also hash their upstream stage's
  own output, per Decision 2).
- `_iter_candidate_files` now uses `discovery.find_json_files([data_dir])`
  instead of a bare `rglob("*.json")` (review finding, PR #210).
- Fixed a real identity-collapse bug this migration surfaced: every
  canonical story file's own leaf name is literally `story.json` now, so
  `path.stem` alone collapsed to `"story"` for every story (both in
  `row["story_id"]` and in the unexpected-per-story-exception fallback
  row in `main()`). New `_story_identity()` combines the collection name
  and the story's own bucket directory name.
- `main()` resolves `working_root=--output`/`source_root=--data-dir` via
  `checkpoint.resolve_roots()`.
- `_run_erw_pipeline` split into `_run_erw_extraction` (stages 2-9) +
  `_apply_cross_segment_relations` (the story-level pass), kept as a
  thin backward-compatible wrapper composing both for the existing
  `TestRunErwPipelineStoryRelationCallSite` regression test.
  `_apply_cross_segment_relations` reconstructs a minimal story object
  (`_MiniStory`/`_MiniSegment`/`_MiniEvent`) from a disk-only checkpoint
  when resuming across a process restart — no `from_dict` exists on
  `schema.py`'s dataclass hierarchy, and building one for all 14
  dataclasses would be substantially more than this stage's own resume
  path needs (confirmed by reading `build_event_index`/
  `build_story_relations`'s actual source: they only ever touch
  `segment_id`/`events[].event_id`/`.predicate`/`.event_type`/
  `.evidence`). The same-run case (erw_extract computed fresh, not from
  a checkpoint) still passes the real `StoryWorldAnnotation` through, so
  full `validate_story_annotation` runs exactly as before the split —
  the reduced-validation path only applies to a process restart landing
  in the narrow window between erw_extract's own checkpoint write and
  cross_segment_relation's, an honestly-documented, narrow scope
  boundary rather than a schema.py change.
- New tests (`run_pilot_test.py`, 8 new + 3 preserved existing, all
  against real pipeline stages, not mocked returns): bounded
  small-scale-trial call counting; a real `KeyboardInterrupt` mid-run
  preserving the already-completed segmentation checkpoint (not an
  ordinary `Exception`, which `main()`'s own per-story `except Exception`
  would swallow); a resumed run not re-issuing the already-checkpointed
  segmentation call; fingerprint invalidation on a model change (and
  reuse under an unchanged one); genre-detect checkpointing across a
  resumed scan; and the discovery-selector fix across multiple
  collections and a sidecar file. Updated
  `TestMainUnexpectedPerStoryException`'s fixture writer from flat-layout
  to bucket layout (the old flat fixtures are no longer discovered at
  all by the new selector), and fixed its `story_id`-keyed assertions and
  its `fake_run_story` closure's `path.stem == "story_b"` check
  (now `path.parent.name`).
- Re-vetted against this session's 8 operational criteria: both hard
  blockers (bounded small-scale trial, crash/interrupt recovery) are
  confirmed resolved by the new test suite directly. Call estimation and
  enhanced progress logging remain out of scope (Category E1, deferred
  per the proposal's own Non-Goals) — never hard blockers.
- Added a "Checkpointing and resume" section to `README.md` and a
  resume note to `running_the_pilot.md`'s real-run step.
- Toolchain drift (black/ruff, and a stale editable install pointing at
  an unrelated worktree) recurred again during this implementation,
  exactly as the 2026-08-02 `feedback_preflight_toolchain_and_editable_install_check`
  memory anticipated; fixed proactively before trusting `scripts/test`.
