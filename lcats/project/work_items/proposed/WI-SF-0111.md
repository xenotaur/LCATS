# Work Item: WI-SF-0111

## Summary

Draft, but do not run, the manifest and runbook for a bounded, no-cost, local-model live test of the `sf_heinlein` stage merged in `WI-SF-0110`, so that the live trials can later be executed and reviewed as a governed procedure.

## Problem / Context

The Heinlein stage in `experimental/science_fiction_analysis_trial/run_worldcon_spike.py` was only exercised with the deterministic fake backend. Paid backends are rejected for `--include-heinlein` by design, because the stage adds a model call per story that no approved paid-run estimate covers. The only live path is therefore a local OpenAI-compatible endpoint with a base URL, such as Ollama, at zero cost.

The Knight/Suvin canary already has a runbook, manifest, and report (`WI-SF-0015`), and its one local trial against `gpt-oss:20b` failed in the shared evidence stage on the negative control (malformed or truncated tool JSON, then a provider 500). The runtime hardening planned by `WI-SF-0017` was resolved as a planning artifact only, and the runner has no JSON repair or `response_format` path, so that failure mode is still open. The ERW `entity_shape_adapter.py` in `experimental/model_comparison/ollama_gpt_oss_20b/` repairs entity extraction output only and is not a substitute.

A single uncommitted probe on 2026-10-06 (one story, `anderson/bell`, Heinlein flag off, `gpt-oss:20b` through Ollama 0.32.5) completed in about 484 seconds: the evidence stage truncated at the default 4096-token output cap on its first attempt and succeeded on the doubled-limit retry, and Knight and Suvin then ran cleanly. The earlier failure did not recur in that run. This is a session observation, not a committed artifact, and one run is not decision-grade, so the failure should be treated as intermittent. The probe also showed a 32768-token server context and the model fully on GPU.

Local resources observed on the host: Ollama 0.32.5 is installed but not running, models present include `gpt-oss:20b`, `qwen3:30b-a3b`, `qwen3:8b`, `gemma4:12b`, and `deepseek-r1:14b`, with 10 cores and 32 GB of memory. The earlier Knight/Suvin local trial took about 16 minutes for two stories.

## Scope

- A new Heinlein canary manifest and runbook; the existing Knight/Suvin canary manifest and runbook are not modified.
- No-cost structural tests for the manifest and the flag-on fake-backend canary.
- The live trials themselves are out of scope and belong to a later work item.

## Required Changes

1. Add `experimental/science_fiction_analysis_trial/manifests/heinlein_canary_manifest.json`. It must use the manifest version string the runner requires and define all four gates (smoke, sample, canary, full), because the loader rejects a missing gate. The canary gate caps each run at two stories, authorizes no paid model calls with zero estimated cost, and lists stop conditions. The loader ignores unknown keys, so per-story expectations may live in the manifest.
2. Choose the two canary stories and record, for each, an operational expectation and a one-line rationale. Candidates from the existing smoke and sample manifests are `mass_quantities/2_b_r_0_2_b__vonnegut`, `anderson/bell`, and `lovecraft/the_colour_out_of_space`. The executor must read the chosen stories before locking expectations, and the expectations are operational checks, not gold labels.
3. Add `experimental/science_fiction_analysis_trial/heinlein_canary_runbook.md`, structured like the Knight/Suvin runbook, covering:
   - Preconditions: a local Ollama server started with `ollama serve`, the model digest recorded, and the context length the server reports recorded (for example from `ollama ps` once a model is loaded), because the repo docs do not state it.
   - Model choice: `gpt-oss:20b` as the default, since it is the most vetted candidate and matches the earlier trial; `qwen3:30b-a3b` as an optional separate candidate. One canary uses one model.
   - Sequence: the deterministic test suite; a fake-backend smoke with `--include-heinlein`; a flag-off local baseline on the same stories; then three local trials with the flag on, each in a new output root with `--max-failures 3`. The flag-off baseline doubles as the evidence-stage precondition: an evidence-stage failure there is recorded as an infrastructure result, not a Heinlein result.
   - Commands set `--max-tokens 8192` explicitly so the evidence stage does not waste a truncated first attempt at the default 4096 cap.
   - Inspection checklist: the raw `sf_heinlein` response and its persisted attempts; any quarantine record; all five criteria present in `analyses.heinlein`; the verdict and interval; each rationale against its cited evidence; no `present` decision without valid evidence; dependency-rule violations quarantined and their frequency noted as a prompt-quality signal; Knight and Suvin results consistent with the flag-off baseline allowing for ordinary model variation; and the detailed rendering and comparison table, with a failed story showing `Unavailable` and a warning.
   - Resource note: roughly 8 minutes per story flag-off and an expected additional 15 percent for the Heinlein stage, so about 18 to 20 minutes per two-story trial and about 80 minutes for the baseline plus three trials.
   - Stop conditions adapted from the Knight/Suvin runbook: invented or silently dropped evidence, a dependency violation accepted without quarantine, a retry without a persisted attempt, any paid call, and uninterpretable provider failure.
   - Report requirements: structural success, results against the pre-set expectations, quarantines and coercions, token usage and latency, repeatability across the three trials, and a proceed, revise, or stop recommendation, without any claim about theoretical accuracy.
   - Paid backends excluded, with a pointer to the separate work needed to cover a fourth model call in a reviewed paid-run estimate (`WI-SF-0016` is the closest existing item).
   - Invalidation: results apply to the current `heinlein-five-v1` rubric wording and must be rerun if the 1947 comparison later forces a `heinlein-five-v2`.
4. Add no-cost tests in `tests/analysis_tests/science_fiction/worldcon_spike_test.py` that the manifest loads through `load_manifest`, the canary gate caps two stories and authorizes no paid calls, a dry-run plan with the flag shows `include_heinlein`, and a fake-backend canary run with the flag completes on the manifest's stories and publishes valid sidecars.
5. Do not run the live trials and do not edit the existing Knight/Suvin canary manifest, runbook, or report.

## Non-Goals

- Do not run live local-model trials, paid model calls, the 10-story sample, or the Worldcon sample.
- Do not claim theoretical accuracy, human agreement, or that the Heinlein wording is edition-final.
- Do not change Knight's or Suvin's definitions, or the `HEINLEIN_FIVE` rubric text.
- Do not harden the evidence stage against malformed local-model output; that is separate work.
- Do not write corpus sidecars or modify corpus promotion or annotation commands.

- Each canary story has a recorded operational expectation and rationale, labeled as an operational check and not a gold label.
- The runbook covers preconditions, the trial sequence, the inspection checklist, stop conditions, report requirements, and the exclusion of paid backends.
- No-cost tests pass, including a fake-backend canary run with the Heinlein flag on the manifest stories.

## Dependencies / Order

None to draft the manifest and runbook. Executing the live trials is blocked in practice by the intermittent local evidence-stage failure, so either evidence-stage hardening lands first or the trials accept evidence-stage failures as recorded infrastructure results. The successor work item that runs the three trials is deliberately deferred until a local server is available and that question is settled.

## Risk Notes

- Expectations chosen without reading the stories could be wrong.
- Local-model output varies from run to run, so a single trial is not decision-grade and three trials plus a flag-off baseline are required before a verdict.
- The evidence stage truncates at the default 4096-token output cap and has failed intermittently on a local model; an evidence-stage failure says nothing about the Heinlein stage.
- A later `heinlein-five-v2` rubric would invalidate any results.
- Local server defaults, such as context length, may differ between machines and sessions, so the runbook must record them for every trial.
- Tool versions on the host may differ from the CI pins; report that separately from repository failures.
