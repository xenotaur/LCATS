# Work Item: WI-SF-0111

## Summary

Draft, but do not run, the manifest and runbook for a bounded, no-cost, local-model live test of the `sf_heinlein` stage merged in `WI-SF-0110`, together with the small runner changes that make its guarantees enforceable: fingerprinted and persisted expectations, and loopback-only no-cost endpoints. This lets the live trials later be executed and reviewed as a governed procedure.

## Problem / Context

The Heinlein stage in `experimental/science_fiction_analysis_trial/run_worldcon_spike.py` was only exercised with the deterministic fake backend. The runner rejects `--include-heinlein` when a paid call is requested, because the stage adds a model call per story that no approved paid-run estimate covers. That guarantee is weaker than it reads: `_paid_call_requested` treats every `openai-compatible` backend with any non-null `base_url` as no-cost, so a remote paid-compatible URL bypasses both the manifest's `paid_model_calls_authorized: false` gate and the Heinlein rejection. This is a gap in merged code, found in review. The intended live path is a loopback OpenAI-compatible endpoint, such as a local Ollama, at zero cost.

Two further gaps were found in review. The manifest loader discards unknown keys, so expectations stored only as extra keys are not loaded, are not part of the manifest fingerprint, and are not recorded in trial artifacts. And the existing canary manifest has no `smoke_stories`, so a smoke run over it selects zero stories and succeeds vacuously.

The Knight/Suvin canary already has a runbook, manifest, and report (`WI-SF-0015`), and its one local trial against `gpt-oss:20b` failed in the shared evidence stage on the negative control (malformed or truncated tool JSON, then a provider 500). The runtime hardening planned by `WI-SF-0017` was resolved as a planning artifact only, and the runner has no JSON repair or `response_format` path, so that failure mode is still open. The ERW `entity_shape_adapter.py` in `experimental/model_comparison/ollama_gpt_oss_20b/` repairs entity extraction output only and is not a substitute.

A single uncommitted probe on 2026-10-06 (one story, `anderson/bell`, Heinlein flag off, `gpt-oss:20b` through Ollama 0.32.5) completed in about 484 seconds: the evidence stage truncated at the default 4096-token output cap on its first attempt and succeeded on the doubled-limit retry, and Knight and Suvin then ran cleanly. The earlier failure did not recur in that run. This is a session observation, not a committed artifact, and one run is not decision-grade, so the failure should be treated as intermittent. The probe also showed a 32768-token server context and the model fully on GPU.

Local resources observed on the host: Ollama 0.32.5 is installed but not running, models present include `gpt-oss:20b`, `qwen3:30b-a3b`, `qwen3:8b`, `gemma4:12b`, and `deepseek-r1:14b`, with 10 cores and 32 GB of memory. The earlier Knight/Suvin local trial took about 16 minutes for two stories.

## Scope

## Required Changes

1. Add `experimental/science_fiction_analysis_trial/manifests/heinlein_canary_manifest.json`. It must use the manifest version string the runner requires and define all four gates (smoke, sample, canary, full), because the loader rejects a missing gate. The canary gate caps each run at two stories, authorizes no paid model calls with zero estimated cost, and lists stop conditions. It must also define a non-empty `smoke_stories` selection (reusing existing smoke stories), because an empty selection makes a smoke run succeed with zero stories. Per-story `expectations` are stored in the manifest and loaded by the runner change in item 3, not as ignored extra keys.
2. Choose the two canary stories and record, for each, an operational expectation and a one-line rationale. Candidates from the existing smoke and sample manifests are `mass_quantities/2_b_r_0_2_b__vonnegut`, `anderson/bell`, and `lovecraft/the_colour_out_of_space`. The executor must read the chosen stories before locking expectations, and the expectations are operational checks, not gold labels.
3. Make two small changes in `experimental/science_fiction_analysis_trial/run_worldcon_spike.py`:
   - Load per-story `expectations` as first-class optional data. Include it in the manifest fingerprint only when present, so the fingerprints of existing manifests, and any paid-run approval snapshots that compare them, are unchanged. Persist a copy of the manifest as `manifest_snapshot.json` in the run's output root when the manifest carries expectations, so trial artifacts show which pre-set expectations were evaluated while runs over manifests without expectations keep their existing file set; a resumed run with a different manifest is refused.
   - Treat an `openai-compatible` endpoint as no-cost only when its `base_url` host is loopback (`localhost`, `127.0.0.0/8`, `::1`). Any other host takes the paid path, so the Heinlein rejection and the paid-run gate apply. LAN-hosted local servers are not supported by this change.
4. Add `experimental/science_fiction_analysis_trial/heinlein_canary_runbook.md`, structured like the Knight/Suvin runbook, covering:
   - Preconditions: a local Ollama server started with `ollama serve` and reached through a loopback URL such as `http://localhost:11434/v1` (any other host takes the paid path), the model digest recorded, and the context length the server reports recorded (for example from `ollama ps` once a model is loaded), because the repo docs do not state it.
   - Model choice: `gpt-oss:20b` as the default, since it is the most vetted candidate and matches the earlier trial; `qwen3:30b-a3b` as an optional separate candidate. One canary uses one model.
   - Sequence: the deterministic test suite; a fake-backend smoke with `--include-heinlein`; a flag-off local baseline on the same stories; then three local trials with the flag on, each in a new output root with `--max-failures 3`. The flag-off baseline doubles as the evidence-stage precondition: an evidence-stage failure there is recorded as an infrastructure result, not a Heinlein result.
   - Commands set `--max-tokens 8192` explicitly so the evidence stage does not waste a truncated first attempt at the default 4096 cap.
   - Inspection checklist: the raw `sf_heinlein` response and its persisted attempts; any quarantine record; all five criteria present in `analyses.heinlein`; the verdict and interval; each rationale against its cited evidence; no `present` decision without valid evidence; dependency-rule violations quarantined and their frequency noted as a prompt-quality signal; Knight and Suvin results consistent with the flag-off baseline allowing for ordinary model variation; and the detailed rendering and comparison table, with a failed story showing `Unavailable` and a warning.
   - Resource note: roughly 8 minutes per story flag-off and an expected additional 15 percent for the Heinlein stage, so about 18 to 20 minutes per two-story trial and about 80 minutes for the baseline plus three trials.
   - Stop conditions adapted from the Knight/Suvin runbook: invented or silently dropped evidence, a dependency violation accepted without quarantine, a retry without a persisted attempt, any paid call, and uninterpretable provider failure.
   - Report requirements: structural success, results against the pre-set expectations, quarantines and coercions, token usage and latency, repeatability across the three trials, and a proceed, revise, or stop recommendation, without any claim about theoretical accuracy.
   - Paid backends excluded, with a pointer to the separate work needed to cover a fourth model call in a reviewed paid-run estimate (`WI-SF-0016` is the closest existing item).
   - Invalidation: results apply to the current `heinlein-five-v1` rubric wording and must be rerun if a later comparison forces a `heinlein-five-v2`, and a wording-only change to the rubric text changes the Heinlein stage prompt, so earlier Heinlein checkpoints are not reused.
5. Add no-cost tests in `tests/analysis_tests/science_fiction/worldcon_spike_test.py` that:
   - the manifest loads through `load_manifest`, the canary gate caps two stories and authorizes no paid calls, and the smoke selection is non-empty;
   - a dry-run plan with the flag shows `include_heinlein`;
   - a fake-backend smoke run processes the manifest's smoke stories (a non-zero count) and publishes Heinlein verdicts, and a fake-backend canary run with the flag completes on the canary stories and publishes valid sidecars;
   - changing a story expectation changes the manifest fingerprint, while the fingerprints of the existing manifests are unchanged (asserted against values recorded before the change);
   - a run over a manifest with expectations persists the manifest copy, a run over one without writes none, and a resume with an edited manifest is refused;
   - loopback `base_url` values (`localhost`, `127.0.0.1`, `[::1]`) count as no-cost, and a remote host takes the paid path so `--include-heinlein` is rejected.
6. Do not run the live trials and do not edit the existing Knight/Suvin canary manifest, runbook, or report.

## Dependencies / Order

None to draft the manifest and runbook. Executing the live trials is blocked in practice by the intermittent local evidence-stage failure, so either evidence-stage hardening lands first or the trials accept evidence-stage failures as recorded infrastructure results. The successor work item that runs the three trials is deliberately deferred until a local server is available and that question is settled.

## Risk Notes

- Expectations chosen without reading the stories could be wrong.
- Local-model output varies from run to run, so a single trial is not decision-grade and three trials plus a flag-off baseline are required before a verdict.
- The evidence stage truncates at the default 4096-token output cap and has failed intermittently on a local model; an evidence-stage failure says nothing about the Heinlein stage.
- A later `heinlein-five-v2` rubric would invalidate any results.
- Local server defaults, such as context length, may differ between machines and sessions, so the runbook must record them for every trial.
- Restricting the no-cost path to loopback blocks LAN-hosted servers, which is intentional here.
- The fingerprint change must not alter existing manifests' fingerprints, or it would invalidate paid-run approval snapshots that compare them.
- Tool versions on the host may differ from the CI pins; report that separately from repository failures.
