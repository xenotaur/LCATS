# Work Item: WI-SF-0127

## Summary

Add the separate, opt-in analysis stage that extracts a story's material factual premises with their standing timelines and assesses `essential` and `causal` in the author's frame, producing the input that the WI-SF-0126 derivations turn into statuses and a profile. This item adds the stage, its prompt and schema, the runner flag, the paid-run gate rule and fake-backend support, and runs no live model.

## Problem / Context

The proposal chooses a separate stage with its own prompt version, leaving the five-criterion record untouched (decision D9 and option O4). The pattern to follow is the Heinlein stage: an opt-in flag (`run_worldcon_spike.py:163`), its own prompt version (`:63`), appended last, emitted only when present. The proposal's Compatibility list names the runner touch points: `RunnerOptions` and the flag, `StoryResult`, `_sidecar_configuration`, the completed-stage lists, the fake backend, the run summary, and the paid-run gate (`:2991`) that currently rejects the Heinlein stage on any paid-call backend and needs its own rule. Per-attempt request records from WI-SF-0120 apply to the new stage unchanged.

Owner decisions fixed as inputs: the time of a setting is never itself a difference and a stipulated departure from history is a `counterfactual_divergence` premise judged on its enabling mechanism (the prompt must say so); `contested` gives `ambiguous`; `human` is copied from the existing record in the first implementation and compared in the live run (WI-SF-0131); the stage must name each fact and date and mark them `model_asserted` so a later table can audit them.

### Duplication search
- In-repo: the Heinlein stage is the pattern, not a duplicate. Recommendation: proceed.

### Demand search
- The proposal's Implementation Plan item 2. No other item covers it. Recommendation: no action.

## Scope

- The stage, prompt, tool schema, flag, gate rule, fake backend and no-cost tests in `run_worldcon_spike.py` and its tests.
- The runbook gains a short section stating the new stage is opt-in and has not been run live.

## Required Changes

1. Add the opt-in flag and `RunnerOptions` field, the prompt version constant, the system prompt and tool schema, and the stage payload including the date inputs (WI-SF-0128 supplies richer inputs later; accept an optional owner-supplied interval now).
2. Derive `essential`, `causal`, premises and timelines from the model response, validate them with the WI-SF-0126 validators, and derive every status, relation, flag and profile in Python.
3. Select the source Heinlein analysis for `human` by rule (current, complete, matching `story_hash` and `evidence_set_id`), persist its ID, and include it in the stage fingerprint inputs.
4. Record the analysis date and model knowledge cutoff, and add the paid-run gate rule for the stage.
5. Add fake-backend support and tests, including that a raising backend still leaves request records.

## Non-Goals

- No live or paid run (WI-SF-0131), no change to the five-criterion prompt or fingerprints, no rubric change.
- No date-source evaluation (WI-SF-0128), no fact table (WI-SF-0129).

## Acceptance Criteria

- A flag-gated stage exists, modelled on `include_heinlein`, with its own prompt version, its own tool schema, appended last, and emitted only when it ran, and enabling or disabling it does not change any existing stage fingerprint or checkpoint
- The prompt and schema produce the premises (with kind, materiality, anchors and standing timelines, each fact and date marked model_asserted), a composition interval from the supplied date inputs, and the author-frame `essential` and `causal` statuses citing premise IDs
- `human` is copied from the selected current complete Heinlein analysis whose `story_hash` and `evidence_set_id` match, the source analysis ID is persisted and is a fingerprint input, and a missing or failed source gives `human: not_computed` without failing the stage
- The analysis date and the model knowledge cutoff are recorded with every result, and the paid-run gate rejects the stage on any paid-call backend with its own rule
- Fake-backend tests cover success, a malformed response, a raising backend (request records still written), and the omitted-when-disabled case, no paid or live call is made, and `lrh validate` reports 0 errors
- Experiment coverage is established explicitly: the changed runner is formatted and linted by explicit path (the default package scripts cover only `src tests tools`), and the documented fake-backend smoke from `heinlein_canary_runbook.md` passes with the new flag and processes both smoke stories

## Risk Notes

- A new prompt invites the silent key-mismatch failure seen in WI-SF-0113 (the local model ignored tool-schema key names); the schema validator must reject rather than discard unknown keys.
- A premise list from a local model may be unstable between runs; stability is measured in WI-SF-0131, not assumed here.
- The stage's author-frame `essential` and `causal` depend on the model reading the frame correctly; this is checked live, not by fakes.
