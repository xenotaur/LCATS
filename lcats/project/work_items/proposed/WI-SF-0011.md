# Work Item: WI-SF-0011

## Summary

Design the separately authorized production corpus integration gate for science-fiction sidecars after Phase 3 reports an integrate/revise/stop decision.

## Problem / Context

The Knight/Novum proposal explicitly keeps Phases 1-3 experiment-local and reserves production integration for a later gate (`project/design/proposals/adopted/knight-novum-analysis-sidecar/00_proposal.md:565`). This item captures that gate as design work only, so successful pilots do not silently authorize corpus-wide writes or production command changes.

### Duplication search
- In-repo: No production integration design for `science-fiction.json` exists.
- Sibling repos: None identified.
- External libraries: None applicable.
- Recommendation: Proceed only after Phase 3 decision evidence exists.

### Demand search
- Work items: No existing WI covers this integration gate.
- Proposals: `PROP-LCATS-KNIGHT-NOVUM-ANALYSIS-SIDECAR` requires later corpus integration to be separately authorized.
- Backlog: No matching backlog entry found.
- Recommendation: Link to `WS-KNIGHT-NOVUM-ANALYSIS`.

## Scope

- Design the production path for science-fiction sidecars if Phase 3 recommends integration.
- Address canonical filename, survey/promotion validation, transaction-safe promotion, annotation entry point, canaries, rollback, append-only evolution, and corpus-wide reporting.
- Keep the design separate from implementation and corpus writes.

## Required Changes

1. Create `project/design/proposals/proposed/science-fiction-corpus-integration-gate/00_proposal.md`.
2. Cite the Phase 3 decision and evidence that motivates integration, revision, or termination.
3. Document the canonical sidecar filename and validation responsibilities.
4. Document promotion/rollback/canary safety, annotation command strategy, append-only evolution, and reporting requirements.
5. Identify follow-up implementation work items if integration is approved.

## Non-Goals

- Do not implement production corpus integration.
- Do not write or promote corpus sidecars.
- Do not modify `lcats annotate` or `lcats promote`.
- Do not make paid model calls.

## Acceptance Criteria

- A proposed integration-gate design addresses canonical sidecar filename, survey and promotion validation, transaction-safe promotion, opt-in annotation or dedicated command, canaries, rollback, append-only evolution, and corpus-wide reporting.
- The design treats production integration as separately authorized work rather than an automatic Phase 3 consequence.
- The design cites Phase 3 decision evidence and explains integration, revision, or termination implications.
- No production implementation, corpus write, promotion change, or paid model call is included.
