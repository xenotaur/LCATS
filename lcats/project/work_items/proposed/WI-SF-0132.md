# Work Item: WI-SF-0132

## Summary

Decide, from the live validation evidence and not before, whether the existing five-criterion Heinlein prompt should change.

## Problem / Context

The existing prompt tells the model to judge plausibility against "established facts available to a general reader" (`experimental/science_fiction_analysis_trial/run_worldcon_spike.py:2566`), which a model applies with today's knowledge, and its `different` rule is a today-relative reading. The proposal leaves the prompt unchanged and adds a separate stage (Open Question 4): no change until the live run shows how the existing prompt behaves on the period stories. Changing the prompt would change the stage fingerprint and invalidate existing checkpoints and possibly sidecars, so the decision needs evidence. This item is the decision point after WI-SF-0131.

### Duplication search
- In-repo: no other item decides this. Recommendation: proceed.

### Demand search
- The proposal's Implementation Plan item 7 and Open Question 4. Recommendation: no action.

## Scope

- A decision record using the WI-SF-0131 results; no code or prompt change.

## Required Changes

1. Read the WI-SF-0131 report and results; extract how the existing record behaved on the period, historical-fiction, alternate-history and date-sensitive stories.
2. Estimate the cost of a change (fingerprints, checkpoints, sidecars) from the proposal's Compatibility list.
3. Write the decision record and present it to the owner; record the owner's decision.
4. If a change is recommended, list the follow-up work items without creating or making them.

## Non-Goals

- No prompt, rubric, fingerprint or contract change; no live run.

## Acceptance Criteria

- A decision record states whether the existing five-criterion prompt changes, stays unchanged, or is superseded by the date-aware stage for the relevant stories, grounded only in the WI-SF-0131 evidence
- The record states how the existing prompt behaved on the period and date-sensitive stories (today-reading effects on `different` and `plausible`), citing the run results, and what a change would cost in fingerprints, checkpoints and sidecars
- If a change is recommended, the record lists the follow-up work item(s) needed and does not make the change; if not, it states why the date-aware stage is sufficient
- The decision is the owner and is recorded as such, the record makes no claim beyond the evidence, and `lrh validate` reports 0 errors

## Risk Notes

- Deciding before the live run exists would repeat the original problem of judging without evidence; the item must not be executed until WI-SF-0131 is resolved.
- The evidence is a small set of stories by one local model; a decision to change the prompt may need a larger sample than this item can provide.
