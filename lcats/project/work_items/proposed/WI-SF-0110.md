# Work Item: WI-SF-0110

## Summary

Finish the Heinlein detector delivered in PR #473 by adding the LLM adjudication stage that produces its decisions, showing its results in the sidecar renderers, and settling which edition's wording the rubric rests on.

## Problem / Context

PR #473 delivered only the deterministic Heinlein layer: the `HeinleinAnalysis` models, sidecar validation, the conjunctive verdict, the dependency rules, and the `HEINLEIN_FIVE` rubric slots. Nothing yet asks a model to judge a story against the five conditions, so the detector cannot score anything. The renderers in `rendering.py` also do not show Heinlein data.

The rubric wording is verified against Heinlein's English text as reprinted in Nota do Tradutor no. 24 (2022), which cites the 1964 Advent edition of Of Worlds Beyond and dates the collection to 1947. The 1947 printing itself has not been compared, so the wording is not edition-final.

### Duplication search

- In-repo: no existing work item, proposal, workstream, roadmap entry, or backlog entry mentions Heinlein. The Knight and Suvin stages in `experimental/science_fiction_analysis_trial/run_worldcon_spike.py` are the pattern to extend, not a duplicate. `WI-SF-0016` covers paid-run approval and does not overlap.
- Sibling repos: none identified.
- External libraries: none identified that can produce LCATS evidence-anchored adjudication records.
- Recommendation: proceed by extending the existing runner and renderers rather than creating a parallel pipeline.

### Demand search

- Work items: none request this. The only record of this demand is the follow-up list in the PR #473 closeout record.
- Proposals: the adopted Knight/Novum proposal requires independent adjudicators over a shared evidence layer, which a third detector fits.
- Backlog: no matching entry found.
- Recommendation: link to `WS-KNIGHT-NOVUM-ANALYSIS`; there is nothing to close.

## Scope

- Verify the Heinlein rubric wording against the 1947 printing and record the outcome.
- Add a Heinlein adjudication stage to the Worldcon spike runner, parallel to the Knight and Suvin stages.
- Add Heinlein results to the Markdown, HTML, and LaTeX renderers and the comparison table.
- Add no-cost tests for the stage and the renderer changes.

## Required Changes

1. Source check, done first because it can change the wording the prompt is built from. Compare the five conditions in the 1947 printing against the Nota do Tradutor 24 reprint. Record the result in `experimental/science_fiction_analysis_trial/definitions.md`. If the wordings differ, update the `HEINLEIN_FIVE` slots in `src/lcats/analysis/science_fiction/rubric/definitions.py` and record a rubric version decision. A difference that changes the meaning of a condition requires a new rubric id (for example `heinlein-five-v2`) with matching changes to `models.HEINLEIN_RUBRIC_VERSION`, the sidecar validator, and the prompt, so that old and new adjudications never claim the same version with different governing text. A wording-only correction that does not change meaning keeps `heinlein-five-v1`, and the decision is still recorded. If the 1947 text cannot be obtained, record that and keep the rubric marked as not edition-final.
2. Add an `sf_heinlein` stage to `experimental/science_fiction_analysis_trial/run_worldcon_spike.py`, parallel to `sf_knight` and `sf_suvin_novum`:
   - a prompt built from the verified `HEINLEIN_FIVE` wording;
   - a `record_heinlein_adjudication` tool schema;
   - conversion of the model's answer into `heinlein.CriterionAdjudication` records and a call to `heinlein.build_analysis`.
   The model supplies only decisions and evidence references. Python computes the verdict and interval and enforces the dependency rules, and an answer that violates them is quarantined rather than repaired by inventing evidence.
3. Persist raw responses, failures, retries, and quarantine records for every Heinlein attempt, using the same partial-success path as Knight. A Heinlein failure must not affect Knight or Suvin results.
4. Add the Heinlein verdict, interval, and five criteria to the Markdown, HTML, and LaTeX output and to the comparison table in `src/lcats/analysis/science_fiction/rendering.py`. Sidecars with no Heinlein data must render exactly as before.
5. Add no-cost tests under `tests/analysis_tests/science_fiction/` for stage success and failure with the fake backend, dependency violations, sidecar assembly with Heinlein data, and unchanged rendering of pre-Heinlein sidecars.
6. Keep Knight and Suvin checkpoint fingerprints unchanged; the new stage must not invalidate their checkpoints.

- Do not change Knight's criteria or Suvin's definitions.
- Do not write corpus sidecars or modify corpus promotion or annotation commands.

## Acceptance Criteria

- The 1947 printing comparison outcome and the rubric version decision are recorded in `definitions.md`. The rubric slots are updated if the wordings differ, and a meaning-changing difference gets a new rubric id with matching model and validator handling.
- A Heinlein stage in the runner passes no-cost fake-backend tests, and the verdict and interval are computed by code rather than supplied by the model.
- The renderers show the Heinlein verdict, interval, and five criteria, and sidecars written before Heinlein render unchanged.
- Raw responses, failures, and retries are persisted for every Heinlein attempt.
- `lrh validate` reports 0 errors.

## Risk Notes

- The 1947 printing may be hard to obtain; the item allows recording that outcome instead of blocking.
- Sidecars persist only the rubric id, so updating the rubric text in place without a version bump would let old and new adjudications claim the same version with different governing text.
- Model output may violate the dependency rules, so the stage must handle that without inventing evidence.
- A new stage changes the runner's prompt version and could invalidate existing checkpoint fingerprints if not isolated.
- Tool versions on the host may differ from the CI pins; report that separately from repository failures.
