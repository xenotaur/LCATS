# Work Item: WI-SF-0013

## Summary

Harden the Knight and Suvin model boundaries so provider-specific formatting differences can be repaired deterministically while semantically unsafe or ungrounded judgments are quarantined.

## Problem / Context

The Worldcon spike currently has strong typed contracts and deterministic derived fields, but its adjudicator normalizers can silently fill missing Knight criteria, drop invalid evidence references, or attach fallback evidence. Local model output has also used a different Knight container shape than the requested array. This item establishes the input packet, structural validation, safe canonicalization, audit findings, and focused tests needed before another live canary.

The work extends the experiment-local runner created by `WI-SF-0012` and follows the evidence layer's existing coerce, validate, anchor, and quarantine pattern. It does not change the source-dependent theoretical definitions; the exact Knight and Suvin governing text remains separately gated by the adopted proposal and rubric source slots.

## Scope

- Strengthen Knight and Suvin input packets, prompts, schemas, and model-boundary validation.
- Add deterministic safe canonicalization with explicit normalization findings.
- Preserve raw and canonical output while quarantining semantically unsafe results.
- Add focused tests for recoverable and unsafe malformed outputs.

## Required Changes

1. Add a versioned adjudication input contract containing the story hash, evidence-set ID, valid evidence IDs, paragraph IDs, allowed states, and stage metadata.
2. Strengthen the Knight prompt and external schema to require exactly seven criteria; prefer a fixed criterion-key object externally while retaining the ordered internal model.
3. Keep Suvin candidate cardinality variable, allow zero candidates, and represent an absent dominant novum explicitly as `null`.
4. Add safe canonicalization for documented alternate shapes, whitespace/case variants, scalar-to-list fields, numeric strings, and known identifier aliases; record every coercion.
5. Reject or quarantine missing decisions, unknown IDs, invalid evidence references, unsupported statuses, present judgments without support, and repairs that would invent evidence or theory.
6. Remove unsafe fallback evidence assignment and stop silently dropping invalid evidence references.
7. Preserve raw output, canonical output, validation findings, and quarantine reasons in experiment-local artifacts and run logs.
8. Render intervals as `definite`, `possible`, and `total`, not as an unlabeled two-number score.
9. Add parametrized tests for all-absent, all-ambiguous, all-present, mixed, missing, duplicate, unknown, alternate-shape, malformed-nested, invalid-reference, and no-candidate cases.

## Non-Goals

- Do not change the Knight seven-criterion or Suvin N/C/H theoretical definitions.
- Do not perform paid model calls or run the two-story canary.
- Do not add human annotation, gold labels, Phase 2 thresholds, or corpus integration.
- Do not silently coerce missing evidence into a valid judgment.
- Do not add a production JSON Schema dependency unless an approved design change requires it.

## Acceptance Criteria

- The model boundary rejects or records every missing, duplicate, unknown, or malformed Knight criterion instead of silently manufacturing a decision.
- Known semantically equivalent output shapes canonicalize deterministically and expose their coercions in machine-readable findings.
- Invalid evidence references and unsupported present judgments cannot become successful typed analyses.
- Knight intervals always expose `total_count: 7`; Suvin qualification, dominant pointers, and systems are derived and validated in Python.
- Focused tests cover recoverable and unsafe malformed output, and `lrh validate` reports 0 errors.

## Dependencies / Order

This item follows `WI-SF-0012` and must land before the contract canary. It can proceed without resolving the primary-source rubric gate as long as prompt edits preserve the adopted definitions rather than freezing new theoretical wording.

## Risk Notes

- Overly permissive canonicalization could convert a provider formatting problem into a false analytical success; every repair must be typed, bounded, and recorded.
- Fixed external Knight schemas may improve local reliability but require compatibility adapters for older captured outputs.
- More detailed prompts increase input tokens and may worsen truncation unless output limits are stage-specific.
