# Work Item: WI-SF-0114

## Summary

Stop the optional `sf_heinlein` stage from silently turning mismatched model output into a `complete` analysis. A response whose criterion keys do not match the tool schema must fail loudly into quarantine, a response that arrives as a single Markdown-fenced JSON block is accepted as a recorded coercion, and both behaviors are covered by no-cost tests built from the raw responses the `WI-SF-0113` canary captured. Rerunning the live canary is a later step.

## Problem / Context

The `WI-SF-0113` canary (`experimental/science_fiction_analysis_trial/heinlein_canary_report.md`, PR 487) found that `_heinlein_decisions` in `run_worldcon_spike.py` reads the keys `criterion_id`, `status`, and `supporting_evidence_ids`, while `gpt-oss:20b` through Ollama returned `criterion`, `decision` or `decision_state`, and `evidence_ids` in all six raw responses. A missing `criterion_id` makes every criterion default to `not_assessable` with an empty rationale, and the stage still reports `complete` with no quarantine or coercion record. That contradicts the stage's own rule that a bad decision fails validation and is quarantined, not repaired. In the negative-control story the model's raw answers were all `present`, so the stored result hid a likely expectation failure.

Trial 1 also returned a Markdown-fenced JSON block as plain text for one story. `json.loads` rejects it at character 0, which is the designed failure path and worked, but the content was intact.

The tool schema is closed with `strict_tool_schema`, and `openai_backend.py` forwards a `strict` field. The canary showed that Ollama with this model did not constrain the keys. Whether Ollama honors `strict` at all is not confirmed.

The same silent-default pattern exists in `_knight_decisions`, which also substitutes a fallback evidence ID. Knight and Suvin used the correct keys in every canary run, and changing them would alter existing checkpoints, so they are out of scope here.

## Scope

- The Heinlein path in `experimental/science_fiction_analysis_trial/run_worldcon_spike.py` (decision normalization, parse handling, checkpoint fingerprint) and its tests.

- The Knight and Suvin stages, the rubric text, and the persisted canary results are not touched.

## Required Changes

1. **Fail loudly on mismatched keys.** Recommended rule, recorded in the implementation plan for the owner to confirm: a response whose criteria cannot be matched to the five `criterion_id` values is quarantined and the story shows `Unavailable`, through the same path as a `JSONDecodeError`. An explicit alias map (`criterion` to `criterion_id`, `decision` or `decision_state` to `status`, `evidence_ids` to `supporting_evidence_ids`) is the rejected alternative; it is acceptable only if each use is recorded per criterion as a coercion, so a reader can see the model did not follow the schema.
2. **Never default silently.** Any missing criterion, or a missing or invalid status, quarantines the stage. `not_assessable` is accepted only when the model actually returned it. A wrongly shaped response never becomes a complete analysis with empty rationales.
3. **Fenced JSON.** Accept a response that is exactly one Markdown-fenced JSON block, record the coercion in the analysis and as a warning, and treat any other non-JSON text as a quarantined failure.
4. **Investigate key enforcement for local backends.** From the wire request and one single-story local probe, confirm whether Ollama honors the forwarded `strict` field and the closed schema for `gpt-oss:20b`. If it does not, record that the prompt and the post-hoc check are the only controls. Do not add provider-specific workarounds beyond that, and do not edit `openai_backend.py` unless the investigation shows a forwarding bug.
5. **Checkpoints.** Change the Heinlein stage's fingerprint component so checkpoints written under the old behavior, which silently dropped content, are never reused. Keep fingerprints of runs without the Heinlein flag unchanged.
6. **No-cost tests.** Use the six raw responses from the canary results as fixtures, copied with absolute paths removed, and assert that each fixture passes through the real validator. Cover the decision in item 1, the fenced case, a genuine all-`not_assessable` response, a mixed response, and the checkpoint change. Existing Heinlein, Knight, and Suvin tests stay unchanged and green.
7. **Do not rerun the live canary here.** A rerun is a separate work item or an explicit later `/lrh-execute`.

## Non-Goals

## Acceptance Criteria

- A Heinlein response whose criterion keys do not match the tool schema is no longer reported as a complete analysis of `not_assessable` criteria; the stage is quarantined and the story shows `Unavailable`.
- A response that is exactly one Markdown-fenced JSON block is accepted and the coercion is recorded in the analysis; any other non-JSON text is quarantined as a failure.
- The six raw responses captured by the `WI-SF-0113` canary, used as fixtures through the real validator, behave as specified, and a genuine model-returned `not_assessable` is still accepted.
- Heinlein checkpoints written under the old behavior are never reused, and existing Heinlein, Knight, and Suvin tests pass unchanged.
- `lrh validate` reports 0 errors.

## Risk Notes

- Failing loudly turns today's silent `complete` results into `Unavailable` ones, which lowers the apparent success rate for models that ignore the schema keys.
- An alias map is easy to over-extend, which is why it is the rejected alternative and each use would be a recorded coercion.
- The Knight stage has the same latent pattern; a shared helper would be tempting but would change existing checkpoints and fingerprints.
- Fixtures copied from real responses contain story text and evidence IDs; check their size and content before committing.
- `scripts/format` skips `experimental/`, so the runner changes need the pinned black and ruff run directly, and the default environment's tool versions differ from CI's.
