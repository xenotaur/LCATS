# Work Item: WI-SF-0116

## Summary

Run the Heinlein live canary again, with the same manifest, model, and settings, on the code that includes the `WI-SF-0114` fail-loud fix: one flag-off local baseline and three flag-on local trials on the two manifest canary stories, using `gpt-oss:20b` through a loopback Ollama server with `--max-tokens 8192`. Persist every artifact in a new output-root family and write `heinlein_canary_report_v2.md`, which compares against the `WI-SF-0113` report and recommends proceed, revise, or stop. Every call is local and no-cost, and no code changes.

## Problem / Context

The `WI-SF-0113` canary (`experimental/science_fiction_analysis_trial/heinlein_canary_report.md`) found that the pipeline silently discarded the model's Heinlein decisions in six of six raw responses, and that the shared evidence stage gave the Vonnegut story zero usable records in three trials while reporting success. `WI-SF-0114` (PR 490) made those cases fail loudly: a Heinlein response with the wrong keys, missing required fields, or non-string ID lists is quarantined; an evidence response with a missing or non-list `evidence` key, or whose candidates are all quarantined, fails the story; the shared text fallback unwraps exactly one fenced JSON block through the new `strict_fence` option and logs it; and the evidence and Heinlein prompts now name the tool schema's keys. None of this has run against a real model.

The comparison with the first canary is confounded, because the prompts and the code both changed since then; the report must say so. The `WI-SF-0114` investigation of whether Ollama honors `strict` was answered from documents and persisted artifacts only, and its unresolved part was deferred to this rerun.

## Risk Notes

- About 80 minutes of local compute (a planning estimate from the first canary), plus the memory load of a 20B model; the Ollama server may be shared with other sessions, which can distort latency.
- Model output varies from run to run, so three trials of one model are not decision-grade.
- The comparison with the first canary is confounded by the prompt and code changes, and a different model digest would add a second confound, which is why a differing digest stops the run before the first call and needs the owner's decision.
- The committed results contain absolute local paths, as the first canary's did, and are not edited.
- Result files add review noise to the PR; the first canary's set was about 0.8 MB.
- The tools in the default environment differ from the CI pins; the pinned versions live in a scratchpad virtual environment that must be recreated, and must stay off `PATH` when running tests.
