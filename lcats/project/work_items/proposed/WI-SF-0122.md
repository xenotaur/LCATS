# Work Item: WI-SF-0122

## Summary

Make the decision normalizers record evidence IDs that match nothing in the evidence set instead of discarding them silently, and decide per caller whether the stage fails or only warns.

## Problem / Context

`_existing_evidence_ids` in `run_worldcon_spike.py` keeps only the IDs it can map to evidence records and returns the shorter tuple with no record of what was dropped. Its callers include the Heinlein and Knight normalizers and the Suvin decision builders, so a model that cites invented or mistyped IDs can produce a `present` criterion with no supporting evidence and a complete stage. This is the same silent-default pattern WI-SF-0114 removed for Heinlein keys, and WI-SF-0114 listed this function as a follow-up candidate.

### Duplication search
- In-repo: WI-SF-0114 fixed key mismatches and empty evidence sets but left this function alone, by design.
- Sibling repos: none identified.

## Scope

- `_existing_evidence_ids` and all its callers in the runner, with tests.
- Heinlein first; Knight and Suvin only after a checkpoint-impact check.

## Required Changes

1. Audit every caller of `_existing_evidence_ids` programmatically (grep the whole repo, not a hand list) and record, per caller, what an unknown ID currently does and what it should do.
2. Return or record the dropped IDs so each drop produces a run-log event naming the stage, the field and the ID.
3. For Heinlein, decide and implement: a `present` criterion left with no resolvable supporting ID quarantines the stage (consistent with the schema requiring evidence on `present`), while a dropped ID on a criterion that still has resolvable ones only warns.
4. For Knight and Suvin, first check whether changing behavior alters existing checkpoint fingerprints or outputs; change them only if the impact is stated and acceptable, otherwise record the decision to defer and why.
5. Add no-cost tests for each caller class using fixtures built through the real validator, plus a test that existing tests and fingerprints are unchanged where promised.

## Non-Goals

- Do not change the Knight or Suvin prompts, the rubric text, or the evidence builder's existing `type` to `evidence_type` coercion.
- Do not run live trials or edit persisted canary results.

## Acceptance Criteria

- A model response that cites an evidence ID that does not exist in the evidence set leaves a visible record (run-log event or quarantine) instead of being dropped silently
- A `present` Heinlein criterion whose cited evidence IDs all fail to resolve is not reported as a complete, evidenced analysis
- The Knight and Suvin callers are changed only after a recorded checkpoint-impact check, and any change to their fingerprints or outputs is stated
- Existing tests pass unchanged, or each changed expectation is justified in the execution record, and `lrh validate` reports 0 errors

- A shared fingerprint bump invalidates unrelated checkpoints; avoid one unless the impact check demands it.
