# Work Item: WI-SF-0008

## Summary

Execute and report the preregistered approximately 30-story Phase 2 science-fiction feasibility pilot.

## Problem / Context

The Phase 2 pilot is the first empirical gate for the Knight/Novum pipeline and must complete before scaling to the Worldcon pilot (`project/design/proposals/adopted/knight-novum-analysis-sidecar/00_proposal.md:506`). It must use preregistered thresholds and reviewed manifests rather than adapting criteria after observing results.

- Sibling repos: None identified.
- External libraries: None applicable.
- Recommendation: Proceed only after dependencies and approvals.

### Demand search
- Work items: No existing WI executes this pilot.

- Backlog: No matching backlog entry found.
- Recommendation: Link to `WS-KNIGHT-NOVUM-ANALYSIS`.

## Scope

- Execute the preregistered Phase 2 manifest using the experiment-local runner.
- Perform human annotation/adjudication and stratified audits as preregistered.
- Report metrics, costs, failures, stability, whole-story/chunked comparisons, and a proceed/revise/stop recommendation that explicitly gates Phase 3.

## Required Changes

1. Produce `experimental/science_fiction_analysis_trial/results/phase2/` outputs.
2. Produce `experimental/science_fiction_analysis_trial/phase2_report.md`.
3. Include machine-readable metrics for evidence validity, agreement, recall, failures, latency, token use, cost, review time, and repeated-run stability.
4. Compare whole-story and chunked behavior where preregistered.
5. Document whether Phase 2 gates passed, failed, or require revision, and record that failed or revise outcomes block Phase 3 until a separately approved revision or scale decision exists.

## Non-Goals

- Do not change preregistered thresholds after observing results.
- Do not run Phase 3.
- Do not write corpus sidecars or promotion outputs.
- Do not make paid calls unless a reviewed manifest, estimated budget, pinned configuration, and explicit human approval exist.

## Acceptance Criteria

- Phase 2 execution uses the preregistered manifest, approved runner configuration, and reviewed cost controls.
- Results report evidence validity, agreement, recall, failure taxonomy, latency, token usage, dollar cost, review time, and repeated-run stability.
- Whole-story versus chunked behavior and independent Knight-only versus Suvin-only audit subsets are reported.
- The Phase 2 report states whether gates passed, failed, or require revision, and records that failed or revise outcomes block Phase 3 until a separately approved revision or scale decision exists.
