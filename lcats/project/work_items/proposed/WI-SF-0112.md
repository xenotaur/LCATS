# Work Item: WI-SF-0112

## Summary

Execute the procedure in `experimental/science_fiction_analysis_trial/heinlein_canary_runbook.md`: one flag-off local baseline and three flag-on local trials on the two canary stories in `manifests/heinlein_canary_manifest.json`, using `gpt-oss:20b` through a loopback Ollama server with `--max-tokens 8192`. Persist every artifact, then write `heinlein_canary_report.md` with a proceed, revise, or stop recommendation. Every call is local and no-cost.

## Problem / Context

The optional `sf_heinlein` stage has only run against the deterministic fake backend, so its behavior against a real model is untested. `WI-SF-0111` built the manifest, the runbook, persisted per-story expectations, and the loopback-only no-cost rule, but ran nothing live.

The Knight/Suvin local trial (`WI-SF-0015`) failed in the shared evidence stage on the negative control. A later one-story probe did not reproduce the failure, so it is intermittent. An evidence-stage failure says nothing about the Heinlein stage and must be reported separately. A single local run is not decision-grade, which is why the runbook requires a baseline plus three trials.

## Scope

- The runbook sequence on the two manifest canary stories only: `mass_quantities/2_b_r_0_2_b__vonnegut` (expected positive) and `anderson/bell` (negative control).
- The deliverables are persisted result artifacts and one report.
- Execution is intended to run separately through `/lrh-execute` after this item's PR merges.

## Required Changes

1. Check the preconditions and record them: a loopback Ollama server is reachable, the model digest and the loaded context length are noted, the manifest fingerprint is noted, the CI-pinned tools are in use, and `scripts/test` passes.
2. Run the fake-backend smoke with `--include-heinlein`. It must process both smoke stories and publish a verdict for each.
3. Run the flag-off local baseline on the two canary stories. An evidence-stage failure here is an infrastructure result, not a Heinlein result.
4. Run three flag-on trials, each in a new output root with `--max-failures 3`, inspecting each against the runbook checklist before starting the next.
5. Write `experimental/science_fiction_analysis_trial/heinlein_canary_report.md` with the contents the runbook requires: structural success, results against the pre-set expectations, quarantines and coercions, token usage and latency, repeatability and agreement with the baseline, evidence-stage failures kept separate, and a proceed, revise, or stop recommendation.
6. Commit the output roots and the report. Keep them outside `data/`, `corpora/`, and any promotion path.
7. Honor the runbook stop conditions. If one fires, record what happened and stop. Do not fix code inside this item; a defect found becomes a follow-up work item.

## Non-Goals

- Do not run paid model calls, a non-loopback endpoint, the 10-story sample, the Worldcon sample, or full mode.
- Do not edit the manifest expectations once a trial has started.
- Do not claim theoretical accuracy, human agreement, or Phase 2 validation.
- Do not harden the evidence stage; that is separate work.
- Do not run a second model. `qwen3:30b-a3b` would be a separate item.
- Do not write corpus sidecars or modify promotion or annotation commands.

## Acceptance Criteria

- The flag-off baseline and the three flag-on local trials are each persisted in their own output root before the next starts, and each root holds a manifest snapshot identical to the manifest used. If a runbook stop condition fires, the runs attempted up to the stop are persisted with their diagnostics and the report names the stop condition; that outcome satisfies this criterion.
- Every `present` Heinlein decision has valid supporting evidence and every dependency violation is quarantined, or the report names exactly which stop condition fired.
- `heinlein_canary_report.md` records results against each case's pre-set expectation, evidence-stage failures separately from Heinlein-stage results, token usage and latency, and the model digest and context length.
- The report ends with a proceed, revise, or stop recommendation and does not claim theoretical accuracy, human agreement, or Phase 2 validation.
- `lrh validate` reports 0 errors.

## Risk Notes

- About 80 minutes of local compute (a planning estimate from one probe), plus the memory and thermal load of a 20B model.
- Model output varies between runs, so a single trial is not decision-grade.
- An evidence-stage failure can make a trial unusable; report it, do not retry until it passes.
- Large result files can swell the PR and the bot review cost, so commit a compact artifact set.
- The expectations are operational checks, not gold labels.
- A later `heinlein-five-v2` rubric would invalidate the results.
- Tool versions on the host may differ from the CI pins; report that separately from repository failures.
