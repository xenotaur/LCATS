# Work Item: WI-SF-0133

## Summary

Prepare the reviewed, paid-model execution package required before the formal Phase 2 Knight/Novum feasibility pilot can begin.

## Problem / Context

`WI-SF-0008` is the formal approximately 30-story Phase 2 execution item, but the repository currently has only the preregistered sample manifest and a separate Worldcon-spike approval package. The Phase 2 preregistration requires a run-specific code/model/configuration record, budget, output root, retry policy, and concurrency, while its human annotation protocol requires independent labels and adjudicated gold records. This item supplies those missing preparation artifacts without running the pilot or inventing annotations.

The confirmed defaults are `claude-opus-4-8`, temperature `0.0`, a `$5` paid canary cap, and a `$50` hard cap for the formal Phase 2 package. These are approval ceilings; actual spend must be measured during execution.

### Duplication search

- In-repo: Related but not duplicate: `WI-SF-0008` executes the formal Phase 2 pilot; `WI-SF-0012` is an explicitly non-Phase-2 Worldcon spike; the existing Opus package is for the Worldcon spike rather than Phase 2.
- Sibling repos: None identified.
- External libraries: None identified; the package should reuse existing LCATS manifest, checkpoint, sidecar, and validation conventions.
- Recommendation: Proceed with a dedicated Phase 2 preparation item.

### Demand search

- Work items: `WI-SF-0008` requests the later formal Phase 2 execution and is the direct downstream consumer.
- Proposals: `PROP-LCATS-KNIGHT-NOVUM-ANALYSIS-SIDECAR` requests the gated Phase 2 pilot.
- Backlog: No separate Phase 2 paid-package entry found.
- Recommendation: Link `WI-SF-0133` to `WI-SF-0008`; do not close either item automatically.

## Scope

- Create the Phase 2 paid execution manifest and approval document.
- Create annotation and adjudication templates that preserve independent labels and gold-record lineage.
- Define the runbook, output layout, audit/repeat subsets, cost accounting, and stop conditions.
- Keep all artifacts experiment-local and separate from corpus promotion.

## Required Changes

1. Create `experimental/science_fiction_analysis_trial/manifests/phase2_opus_run_manifest.json` with the preregistered sample reference, exact story count, code/configuration fingerprints, Opus settings, token/cost estimates, `$5` canary cap, `$50` hard cap, retry policy, concurrency, output root, and stop conditions.
2. Create `phase2_paid_approval.md` documenting the human approval fields, approval status, budget calculation, and the prohibition on calls before review.
3. Create annotation and adjudication templates for independent Knight/Suvin labels, evidence anchors, disagreements, and gold records.
4. Create `phase2_runbook.md` describing preflight validation, canary, formal 30-story execution, audit/repeat subsets, resumability, quarantine, metrics, and closeout.
5. Keep `WI-SF-0008` as the downstream execution item; do not run it, alter its preregistered thresholds, or claim Phase 2 results in this item.
6. Run `lrh validate` and item-specific structural checks.

## Non-Goals

- Do not make paid or local model calls.
- Do not execute `WI-SF-0008`.
- Do not create human labels or adjudicated gold labels.
- Do not change the preregistered sample or thresholds.
- Do not write corpus sidecars or run promotion commands.
- Do not prepare Phase 3 or the 146-story Worldcon run.

## Acceptance Criteria

- The manifest and approval document freeze all required paid-run inputs and approval limits.
- Annotation and adjudication templates are structurally complete but contain no fabricated labels.
- The runbook is sufficient for an independent operator to execute the preregistered Phase 2 plan without choosing settings after observing results.
- Output roots and safeguards prevent corpus or promotion writes.
- `lrh validate` reports 0 errors.

## Risk Notes

- The existing Opus approval package is for the Worldcon spike and must not be silently reused as Phase 2 approval.
- A `$50` ceiling is a proposed hard limit, not a guarantee that the preregistered workload fits within it.
- Annotation templates can define the process but cannot substitute for actual independent human labels.
- A manifest or runbook that leaves fingerprints or retry behavior unspecified would recreate the current execution blocker.
