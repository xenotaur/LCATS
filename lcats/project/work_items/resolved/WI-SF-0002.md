# Work Item: WI-SF-0002

## Summary

Implement deterministic story preparation for the science-fiction analysis pipeline: normalized loading, story hashing, stable paragraph anchors, whole-story eligibility, and paragraph-aligned adaptive chunk manifests.

## Problem / Context

The proposal requires each story to be prepared and indexed once, then reused by all downstream evidence and adjudication stages (`project/design/proposals/adopted/knight-novum-analysis-sidecar/00_proposal.md:203`). Current LCATS story discovery already treats `<story>/story.json` as canonical and excludes sibling sidecars (`src/lcats/analysis/corpus/discovery.py:63`), so this work should extend that layout rather than introducing a parallel source format.

### Duplication search
- In-repo: No science-fiction preparation/chunk-manifest module exists. Related story-bucket discovery and checkpointing patterns exist and should be reused.
- Sibling repos: None identified.
- External libraries: None required for deterministic paragraph planning.
- Recommendation: Proceed.

### Demand search
- Work items: No existing WI provides this science-fiction preparation layer.
- Proposals: `PROP-LCATS-KNIGHT-NOVUM-ANALYSIS-SIDECAR` requests this as Phase 1B.
- Backlog: Historical chunking references exist, but no open duplicate item was found.
- Recommendation: Link to `WS-KNIGHT-NOVUM-ANALYSIS`.

## Scope

- Load normalized story text from canonical story buckets without source mutation.
- Produce deterministic story hashes, stable paragraph IDs, whole-story eligibility decisions, and adaptive chunk plans.
- Ensure chunk manifests provide gap-free coverage, explicit overlap accounting, and versioned configuration.

## Required Changes

1. Create `src/lcats/analysis/science_fiction/preparation.py` and package scaffolding as needed.
2. Implement deterministic story hashing over normalized analysis text.
3. Implement stable paragraph identifiers and paragraph-aligned chunk planning.
4. Detect preferred chapter or section boundaries when present and use them without breaking paragraph coverage.
5. Add tests for whole-story eligibility, chunk threshold configuration, overlap accounting, gap-free coverage, stable manifests, and source immutability.

## Non-Goals

- Do not extract evidence, adjudicate Knight or Suvin judgments, assemble sidecars, or run pilots.
- Do not make paid model calls.
- Do not modify source `story.json` files or production corpus data.
- Do not modify `lcats annotate` or `lcats promote`.

## Acceptance Criteria

- Story loading accepts canonical story-bucket `story.json` inputs without mutating source files.
- Deterministic story hashes, stable paragraph IDs, eligibility decisions, adaptive chunk plans, overlap accounting, and manifests are covered by unit tests.
- Chunk planning provides gap-free paragraph coverage and prefers detected chapter or section boundaries when available.
- Initial chunk thresholds are explicit configurable versioned inputs rather than hidden constants.

## Dependencies / Order

This is the recommended first no-cost Phase 1 implementation leaf after proposal adoption, planning PR landing, readiness review, and explicit selection. `WI-SF-0003` and `WI-SF-0005` depend on its stable story hashes and anchors.
