# Work Item: WI-SF-0016

## Summary

Streamline the approval path for explicitly user-authorized paid Knight/Novum feasibility runs while preserving strong spend, scope, persistence, and promotion safeguards. The agent should work with the user to complete only the missing operational fields, and the runner should automatically persist the resolved approval and post-stage decision instead of requiring the user to prepare and deliver a separate approval package.

## Problem / Context

The current Worldcon runner correctly refuses paid calls unless its manifest contains explicit paid authorization, approved backend/model, positive cost and wall-clock estimates, and stop conditions (`experimental/science_fiction_analysis_trial/run_worldcon_spike.py:2312-2368`). The experiment manifest currently defaults those paid fields to disabled or zero (`experimental/science_fiction_analysis_trial/manifests/worldcon_spike_manifest.json:19-42`).

The repository documentation also requires a reviewed manifest and explicit paid approval (`experimental/science_fiction_analysis_trial/README.md:62-64`), while the Knight/Novum workstream requires a reviewed cost manifest, pinned configuration, and explicit approval before the Worldcon pilot (`project/workstreams/proposed/WS-KNIGHT-NOVUM-ANALYSIS.md:89-93`).

These controls are appropriate for preventing unrequested remote spend, but the current workflow has no conversational completion path. When a user has explicitly authorized a staged paid run, the agent should gather missing values, produce the approval snapshot, and continue after one concise confirmation rather than requiring the user to independently create and deliver governance artifacts.

The runner already persists stage attempts, token usage, checkpoints, and resumable outputs. However, its summary records token totals rather than an actual cost-control ledger (`experimental/science_fiction_analysis_trial/run_worldcon_spike.py:140-164`, `experimental/science_fiction_analysis_trial/run_worldcon_spike.py:2415-2424`). This item adds the minimum durable approval and budget accounting needed to make the existing gate usable for urgent, explicitly authorized experiments.

## Scope

- Add an agent-completable approval workflow for explicitly authorized paid experiments.
- Generate and persist an approval snapshot before the first paid call.
- Preserve stage-specific and cumulative budget limits.
- Record stage decisions only after stage results exist.
- Retain default-deny behavior for missing authorization, scope, model, or budget.
- Update the runbook and focused tests to describe the streamlined workflow.

## Required Changes

1. Define the minimum approval fields:
   - user authorization;
   - backend and model;
   - stage and story count;
   - source-manifest path, commit, and hash;
   - output root;
   - stage budget and cumulative budget;
   - retry policy;
   - no-promotion restriction;
   - stage stop conditions.

2. Allow the agent to populate missing approval fields interactively from the user’s explicit request and ask only for materially ambiguous values.

3. Write an immutable `approval_snapshot.json` into the stage output root before the first paid call.

4. Include the effective code commit, manifest fingerprint, prompt/schema/configuration fingerprints, and generation settings in the snapshot or generated run manifest.

5. Add stage-specific and cumulative budget accounting. The runner must stop before starting another story when the next call would exceed the approved limit and must preserve all completed artifacts.

6. Distinguish:
   - `pending`;
   - `proceed`;
   - `proceed_with_limitations`;
   - `stop_and_revise`;
   - `stop_for_budget`.

   These decisions must be generated after stage inspection, not required in advance.

7. Preserve the existing restrictions against corpus sidecars, promotion commands, production integration, and theoretical-accuracy claims.

8. Add focused tests for:
   - missing approval fields;
   - conversationally completed approval;
   - approval snapshot persistence;
   - stage and cumulative budget limits;
   - resume after budget stop;
   - post-stage decision persistence;
   - rejection of unapproved paid calls.

## Non-Goals

- Do not remove the default-deny paid-call gate.
- Do not authorize paid calls implicitly from ordinary analysis requests.
- Do not implement a general-purpose approval service.
- Do not run paid model calls as part of this implementation item.
- Do not change Knight or Suvin theory.
- Do not modify `lcats annotate`, `lcats promote`, corpus sidecars, or production integration.
- Do not require a pull request solely to authorize an explicitly user-approved experiment.
- Do not claim that budget estimates are exact provider billing unless actual provider cost data is available.

## Acceptance Criteria

- A user who explicitly requests a staged paid run can provide authorization, model, scope, and budget through the conversation; the agent completes the approval record without requiring the user to author a separate package.
- Every paid stage writes an approval snapshot before making the first paid call.
- The snapshot includes the stage budget, cumulative budget, output root, manifest identity, code commit, model, retry policy, and restrictions.
- The runner stops before a new story when the approved stage or cumulative budget would be exceeded and preserves all previous results.
- Stage decisions are written only after persisted stage artifacts are inspected.
- Missing authorization or materially missing scope/budget fields still fail closed.
- Focused tests pass and `lrh validate` reports 0 errors.

## Risk Notes

- A conversational workflow could become unsafe if ordinary discussion is mistaken for paid authorization; explicit live-run language must remain mandatory.
- A token-based estimate may differ from provider billing; the report must distinguish estimated cost from provider-reported or calculated actual cost.
- Budget enforcement may overshoot by one in-flight story unless the runner stops before the next call and uses conservative projections.
- Automatically recorded stage decisions must remain clearly separate from theoretical validation, human agreement, and production-readiness claims.
